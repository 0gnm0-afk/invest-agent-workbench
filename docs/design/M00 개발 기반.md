입력: [3단계 설계](<../3단계 설계.md>) **§8 우선**(§2~4·7 보조), [DESIGN-3-20261117](../../DECISIONS.md#design-3-20261117), [SELECT-2-20261117](../../DECISIONS.md#select-2-20261117), [기능 목록](<../2단계 기능 목록 초안.md>), [기술부채 진단](<../2단계 기술부채 진단.md>) DEBT-01·04·05, [ver3.1](../투자에이전트ver3.1.md), [용어집](../용어집.md).

## 앞 절반 — 설명서

### 1. 하는 일 (세 줄 이내)

개발자가 고친 프로그램을 실제 투자 자료와 분리해서 검사할 수 있게 만든다.
Python 실행 환경을 Codex 앱과 독립시키고, 필요한 프로그램 부품의 버전을 고정한다.
낡은 계좌 시험 자료를 현재의 조회 전용 규칙에 맞춘다.

### 2. 입력과 출력

| 입력 | 출력 |
|---|---|
| 현재 코드·설치 목록·합성 시험 자료 | 같은 구성으로 다시 설치할 수 있는 명세 |
| 검사할 모듈 번호 | 통과·실패·차단·제외를 구분한 검사 결과 |
| 일부러 잘못 만든 요청·경로 | 실제 자료에 닿기 전에 막았다는 결과 |

실계좌 응답이나 운영 DB 사본은 시험 입력으로 쓰지 않는다. 여기서 말하는 합성 자료는 개발자가 만든 가짜 입력이다.

### 3. 저장 위치 (C1 소유 테이블·파일)

M00이 소유하는 운영 DB 테이블은 없다. 설치 명세·실행기·시험 코드는 워크벤치에 둔다. 시험용 DB와 결과 파일은 매 실행마다 운영 폴더 밖의 Windows 임시 폴더에 둔다. 기존 DB·원문·작도·계획은 이동하거나 변환하지 않는다.

### 4. 다른 모듈과의 연결 (§3 계약 ID 인용)

- **C8(§8.2):** 모든 모듈은 M00 실행기로 검사한다. 임시 폴더의 가짜 자료와 컴퓨터 안의 시험용 통신만 허용한다. 실제 자료·인증·외부 네트워크에는 접근하지 않는다.
- **C1(§8.4):** M00은 업무 DB를 소유하지 않는다. 테이블을 쓰는 함수는 각 담당 모듈이 관리하며, 사이클 테이블과 데이터도 그대로 보존한다.
- **C6·C7(§8.3):** 세션 도구는 M09, 화면 연결은 M10 담당이다. M01만 조 1에서 종료 기능 연결을 지울 수 있다.

M00 검수 뒤 M01이 시작한다. 후속 모듈은 자기 검사 목록을 관리한다. 실제 자료 보관·삭제와 대시보드 확인은 구현 검사와 분리해 Claude가 사용자 승인 뒤 진행한다.

### 5. 이번 개편에서 바뀌는 것 / 그대로인 것 / 없어지는 것

- **바뀌는 것:** 워크벤치 Python의 설치 기반, 개발 부품 버전 고정, 하나의 안전한 검사 입구, 시험용 계좌 응답의 성공·실패 표현.
- **그대로인 것:** 계좌 조회 전용 제한, 계좌 성공 확인 규칙, 기존 데이터와 투자 기능. 메리츠 별도 환경과 보류 중인 뉴스 코드는 이번 M00 대상이 아니다.
- **없어지는 것:** 시험이 실제 runtime을 임시 작업장처럼 쓰는 방식과, 보호 장치에 막혔는데도 통과로 보고하는 방식.

### 6. 쓰는 법 (세션에서·대시보드에서)

**세션에서:** 구현자에게 “M00 검사 목록을 보여 줘”, “M00 격리 검사를 실행해 줘”라고 요청한다. 구현 후에는 모듈 번호를 바꾸어 같은 실행기를 쓴다.

**대시보드에서:** 새 버튼이나 화면이 생기지 않는다. 검사하려고 대시보드를 열 필요도 없다. 현재 초안 검토 중에는 위 실행 요청을 수행하지 않는다.

### 7. 사용자가 직접 확인하는 방법 (5단계 검수에 그대로 쓴다)

5단계 [인수 검수](../용어집.md)에서는 구현자가 제공하는 실행기 결과를 확인한다.

1. M00 결과에 독립 Python의 경로·버전과 고정 명세 일치 여부가 표시된다.
2. 계좌 목록이 성공인지 확인하지 못한 가짜 응답은 거부되고, 확인된 빈 목록과 한 시장 실패는 서로 구분된다.
3. 가짜 보호 대상을 건드리는 하위 검사에는 실패가 기록된다. 일반 검사에는 보호 위반이 0건이고, 차단·건너뜀·미확인은 통과 수에 들어가지 않는다.
4. 같은 컴퓨터 안의 시험용 통신과 보호 장치를 물려받은 시험용 자식 프로세스가 동작한다. 외부 연결은 차단된다.

## 뒤 절반 — 작업 지시서

### 1. 범위와 목표

**확정 범위:** DEBT-01·04·05를 M00의 개발 기반 범위에서 처리한다. 조 0에서 단독 구현하고 후속 모듈은 이 결과를 사용한다. 운영 기능의 처리 규칙은 고치지 않는다.

- DEBT-01: `BrokerBoundary`의 성공 목록·중복 목록·빈 목록 오류·시장 오류 보존 기대값을 현행 계약에 맞춘다. 운영 계좌 검증을 느슨하게 만들지 않는다.
- DEBT-04: §8.2의 실행기·모듈 목록·임시 작업공간·Python/Node 보호 장치·독립적인 차단 집계·JSON 영수증을 만든다. 임시 fixture의 loopback(127.0.0.1)·socketpair와 같은 가드를 상속하는 자식 프로세스는 허용한다. 운영 자료 재생·운영 서버·인증·예약은 제외한다.
- DEBT-05: 워크벤치만 독립 Python 기반으로 재현할 수 있게 실행·개발 의존성과 `src`·`scripts` import 경로를 고정한다. 정확한 배포판·패치 버전·설치물 해시는 구현 시 로컬 제공물과 호환성을 확인해 설치 명세에 기록한다. 확인 전 임의 버전 번호를 확정하지 않는다.

**권장안:** 기존 `unittest`를 Python 기본 실행 방식으로 유지한다. pytest를 추가하는 것만으로 격리를 대신하지 않는다. Node 검사는 별도 자식 실행으로 집계하되, 아래 보호 장치를 적용할 수 없는 검사는 차단/미검증으로 남긴다. 앱·캐시 밖의 x64 Python 3.12 호환 배포판을 먼저 검토하고 큰 버전 변경을 섞지 않는다.

경로 약어: `P` = `D:/03.투자에이전트`, `WB` = `P/01.개발/invest-agent-workbench`. 아래 코드 경로는 WB 기준이다. 줄 번호는 2026-11-17에 직접 읽은 소스의 시작 줄이며 구현 직전에 다시 확인한다.

### 4. 단계별 구현 순서

1. **범위와 환경 재현 정보를 고정한다.** WB 변경 목록을 확인하고 다른 작업을 보존한다. 현재 Python의 아키텍처·버전과 배포판 metadata·직접 설치 commit·`.pth`를 비밀값 없이 정리한다. 선택한 독립 Python의 버전·설치물 해시와 로컬 설치 자료를 고정한다. 잠금 명세 생성/설치는 별도 명시 작업이며 검사 명령에서 네트워크 설치를 시도하지 않는다.
2. **등록 목록부터 만든다.** `tests/suites/Mxx.txt`를 해당 모듈의 유일한 선택 목록으로 읽는다. **권장 문법:** 한 줄에 unittest의 `module.Class.test_method` 노드 ID 또는 WB 상대 Node `.cjs` 경로를 적고 빈 줄·`#` 주석은 건너뛴다. 제외 대상과 이유는 주석·결과 영수증에 남긴다. 모듈 번호는 M00~M13 중 하나다. `--node`는 등록된 노드의 부분 선택만 허용하고 전체 모듈 통과와 구분한다. 경로 탈출·중복·미등록/누락 파일·실행 노드 0개는 오류다. 전체 자동 탐색이나 임의 shell/argv는 제공하지 않는다. 다른 모듈의 목록은 해당 모듈이 소유한다.
3. **업무 import 전에 격리한다.** 실행기는 운영 config/runtime/DB를 복사하지 않고 검토한 `src`·`scripts`·`dashboard` 소스와 선택 시험만 OS 임시 작업공간에 준비한다. 가짜 config·DB·mother/root와 비식별 입력만 만든다. `cwd`, `TEMP/TMP`, bytecode/Matplotlib cache/결과 위치도 그 안으로 제한한다. 자식 환경은 필요한 시스템 경로와 합성 값만 명시해 구성하며 부모의 사용자 환경변수·키·시크릿·토큰을 복사·조회·출력하지 않는다. Python 배포판·표준 라이브러리·잠긴 설치 패키지·코드만 읽기 허용하고 운영 데이터와 자격 경로는 읽기까지 거부한다.
4. **보호 장치를 먼저 검증한다.** Python 파일 열기/열거/쓰기/이동/삭제·SQLite URI·DNS·socket·자식 프로세스를 검사한다. 정규화한 절대 경로, `..`, 다른 드라이브, SQLite `file:` URI, 링크/접합 경유를 검사한다. native 호출·DPAPI·레지스트리/사용자 환경변수 조회로 우회할 수 있는 인증 경로는 대체하고 기본 거부한다. Node는 preload 가드와 제한된 실행 환경으로 파일·네트워크·프로세스 경계를 적용한다. 보호를 검증하지 못한 자식/실행 파일은 허용하지 않는다. 앱이 예외를 잡아도 별도 사건 기록에 남겨 일반 검사 결과를 실패시킨다.
5. **로컬 통신·자식 경계를 적용한다.** §8.2에 따라 임시 fixture의 127.0.0.1 서버·socketpair와 같은 가드를 상속한 자식 프로세스를 허용한다. 외부 DNS·외부 connect·전체 인터페이스 bind는 차단한다. loopback도 해당 실행이 만든 fixture 주소·포트만 허용해 이미 떠 있는 운영 서버에는 닿지 않게 한다. 자식 가드 준비 확인 전 시험 모듈을 import하지 않고, 임의 명령·가드 없는 자식 실행은 거부한다. PowerShell도 fixture·가드 상속을 입증한 경우에만 허용하며, 못하면 차단/미확인으로 남긴다. 운영 대시보드·MCP·예약 도구·모델 CLI·뉴스 connector는 실행하지 않는다. 시간 초과·중단 시 자식과 handle을 정리하고 불완전 결과는 실패로 남긴다.
6. **기존 fixture를 갱신한다.** 표의 runtime 임시 경로를 공통 fixture로 옮긴다. 누락 파일 시험은 임시 `records`/가격 저장소와 `runtime_paths.ROOT`를 사용하도록 시험에서 주입한다. 성공 메시지를 추가한 계좌 목록/중복 fixture, `account_list_not_confirmed`, US 오류 `pages: []`를 반영한다. 성공 증거 없는 비어 있지 않은 목록, 비-dict 행, 허용되지 않은 endpoint의 transport 미호출을 추가한다. 외부 reader/pages는 모두 fake다.
7. **M00 목록을 실행기에 등록한다.** 위 수정 대상 7개 Python 시험 파일의 합성 노드, 계좌 `BrokerBoundary`, `StoredData`, 신규 가드·환경 검사와 Node 가드 검사를 등록한다. M00의 작은 loopback/socketpair·자식 fixture는 필수다. 기존 HTTP 기능 검사는 M10, 실행 수명 검사는 M12가 정비·소유한다. 레거시 재생·뉴스 인증/서버 검사는 제외 이유를 남긴다. 후속 모듈 검사 전체를 M00 통과로 대체하지 않는다. M08이 직접 조회 코드를 제거할 때는 해당 시험을 M08의 저장 계약 검사로 교체하도록 인계한다(§8.6).
8. **임시 환경에서 재현하고 검사한다.** OS 임시 폴더에 독립 Python 기반 환경을 로컬 설치물만으로 만들고 §6의 M00 실행기로 설치 명세·import·가드·필수 노드를 검증한다. 결과 JSON도 OS 임시 폴더에만 남긴다. 실제 WB `.venv` 전환과 운영 앱 확인은 아래 운영 적용으로 분리한다.

아래 시험명은 **새로 만들 검사 이름**이다. 기존 통과 실적이 아니다. 모두 §8.2의 M00 실행기 안에서 돌며, 실제 환경 전환·runtime·DB 대조·운영 앱 확인은 구현 완료 조건이 아니다.

### 6. 검사 명령 (M00 실행기 기준, 운영 runtime·DB·외부 네트워크 0)

**§8.2 확정 규약이며, 현재 실행기가 존재하거나 통과했다는 뜻은 아니다.** 구현·승인 후 WB에서 실행한다. 아래 경로는 구현자가 로컬 설치물로 재현한 임시 독립 환경의 실제 경로로 치환한다. 실행기는 설치를 수행하지 않는다.

```powershell
$TestPython = '<임시 독립 환경>/Scripts/python.exe'
# tests/suites/M00.txt의 필수 노드 실행. AC09 확인에는 같은 명령을 두 번 사용
& $TestPython -B tests/run_isolated.py --module M00
# 일부만 다시 확인할 때. 노드 ID는 M00.txt에 등록된 값으로 치환
& $TestPython -B tests/run_isolated.py --module M00 --node '<등록된 노드ID>'
```

- 후속 모듈은 번호만 바꾼다. 예: `--module M12`는 `tests/suites/M12.txt`를 읽는다. 각 모듈 작성자가 자기 목록과 시험을 추가한다. `--node` 부분 실행은 모듈 전체 완료의 근거가 아니다.
- 결과는 OS 임시 폴더의 모듈별 JSON과 콘솔 요약으로 낸다. 필드는 모듈·Python/Node 버전·선택/실행/통과/실패/차단/제외 수·노드별 사유·guard 사건·임시 결과 위치다. 값이나 traceback에 인증정보가 들어가지 않게 한다.
- 종료코드 권장안: 0=선택된 필수 노드와 가드 통과, 1=검사 실패/차단/필수 미실행, 2=목록·환경·격리 설정 오류. JSON에는 전체/부분 실행을 구분하고 차단·skip·미확인을 따로 집계한다.
- 운영 runtime/DB·외부 네트워크를 허용하는 우회 옵션은 만들지 않는다. 가드 미준비·Node 부재·잠금 불일치도 건너뛴 성공으로 처리하지 않는다.

### 7. 브랜치·커밋 방법 (워크벤치 브랜치 `module/Mxx-이름`, 공통 Git은 문서만)

**향후 구현 단계:** WB의 기존 변경을 확인하고 `module/M00-개발기반` 브랜치에서 이 범위만 구현한다. M00 코드·시험·잠금 명세는 WB Git, 본 문서는 D:/ 공통 Git에만 둔다. 모듈 검수 뒤 조 0 결과를 합치고 M01을 시작한다. 전체 경로 일괄 staging을 하지 않고 변경 경로와 staged diff를 확인한다. `.venv`·자격·임시 결과·운영 자료는 추적하지 않는다. push·배포·예약 재개는 포함하지 않는다.

**현재 문서 초안 작업:** 이 파일만 작성한다. 사용자 지시에 따라 STATUS·DECISIONS·3단계 설계는 수정하지 않으며 시험·설치·커밋하지 않는다.

### 9. 운영 적용(Claude, 사용자 승인)

- 구현 완료와 별개다. Claude가 사용자 승인 뒤 WB `.venv`를 독립 Python 기반으로 전환한다. 기존 환경·설치물의 복구 정보를 확보하고 사용 중인 프로세스는 임의로 종료하지 않는다. 전후 명세·해시를 남긴다.
- `pyvenv.cfg` 문자열 수정이나 다른 경로의 venv 단순 이동으로 전환을 대신하지 않는다. 실패하면 복구하고 중단한다. 전환 후에도 §6과 같은 M00 실행기를 사용한다.
- 실제 runtime·DB 대조와 실제 대시보드 확인이 필요하면 §8.2의 별도 승인 범위와 전후 해시 기록 아래 진행한다. 구현 검사에 운영 자료를 가져오지 않는다. 계좌·수집·Telegram·예약 재개는 이 항목에 포함하지 않는다.
