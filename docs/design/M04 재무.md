# M04 재무

작성: 2026-11-17 · DESIGN-3-20261117 · 상태: **초안·사용자 승인 전** · 조 **2**(M00·M01 뒤)
설계 판정: **설계 가능 / 설계 검토 가능**. [3단계 설계 §8](<../3단계 설계.md>)을 앞선 계약보다 우선한다. 기존 질문 4개는 결정 반영, 남은 질문은 없다. 설명서는 사용자 승인 전이며 시험·운영 실행은 하지 않았다.

## 설명서

### 1. 하는 일

선택한 회사가 실제로 발표한 분기·연간 실적을 출처와 함께 보여 준다.
미국 SEC·국내 DART와 기존 회사 공식 보완 자료를 유지하면서, 나중에 공급처를 바꿀 수 있게 내부 연결을 정리한다.
미래의 [이익 추정치 상향](../용어집.md)을 찾거나 투자 가설을 자동 판정하는 기능은 이번에 만들지 않는다.

### 2. 입력과 출력

- **입력:** 시장을 포함한 종목 키, 조회할 실적 기간, 공식 공시 원문. 기존 지표에 필요한 가격은 저장된 가격만 받는다.
- **출력:** 분기·연간 실제 실적, 계산 근거, 공시 기간·통화·회계 범위, 출처와 저장 시각. 숫자를 확인하지 못하면 이유를 표시하고 0으로 채우지 않는다.
- 갱신이 실패하면 실패 이유와 이전 성공 자료를 구분해서 보여 준다. 이전 값을 새 실적처럼 표시하지 않는다.

### 3. 저장 위치

모두 워크벤치 안의 기존 위치를 유지한다. 새 이관용 DB는 만들지 않는다.

| 위치 | M04가 맡는 내용 |
|---|---|
| `runtime/financials/{종목}/snapshots/{ID}/` | 공시 원문, 표준화한 실적, 계산 결과와 원문 일치 확인값(해시). 과거 묶음은 덮어쓰지 않음 |
| 같은 종목 폴더의 `latest.json`·`attempt.json` | 마지막 성공 자료의 위치와 최근 갱신 시도 상태 |
| `runtime/records.sqlite3`의 `record_*` | `financial_source`·`financial_normalized`·`financial_result`·`financial_manifest` 종류의 보존 기록. M03 소유의 공통 저장 함수를 통해 쓴다(C1·§8.4) |
| `runtime/ohlcv.sqlite3` | M03 소유. 저장 가격과 과거 재무의 고정 가격 참조를 M03 함수로 읽고 보존한다 |

### 4. 다른 모듈과의 연결

- **C1·C2(§8.4):** 공통 기록·가격 저장 함수는 M03이 맡는다. M04는 그 함수를 불러 재무 원문과 고정 가격을 보존한다.
- **C4(§8.4):** 출처 어댑터는 종목·기간을 받아 표준 분기·연간 행과 출처·원문 해시를 돌려준다. SEC/DART와 기존 발행회사 공식 보완 자료(IR PDF)를 같은 어댑터에 둔다.
- **C6·C7:** M05는 저장 실적을 읽고, M09는 세션 도구를, M10은 재무 탭을 연결한다. M04는 이 입구들을 바꾸지 않는다.
- **C8(§8.2):** M00 실행기로 임시 자료만 검사한다. 실제 자료·인증·외부 통신은 사용하지 않는다.

### 5. 이번 개편에서 바뀌는 것 / 그대로인 것 / 없어지는 것

- **바뀌는 것:** 출처를 고르는 부분과 실적 계산·보존 부분을 분리하는 [리팩터링](../용어집.md). 공급처가 바뀌어도 표준 실적과 근거를 받는 방식은 유지한다.
- **그대로인 것:** 실제 공시 수치, 기존 계산·결측 이유·기간 비교 규칙, 원문·과거 결과 보존, 명시 요청 때만 수집하는 방식, 재무 탭.
- **없어지는 것:** M04에서 종료하는 사용자 기능은 없다. 종료 기능 제거는 M01, 뉴스는 보류다. Koyfin·FnGuide 연결과 유료 구독은 장기 과제이며 이번에 실행하지 않는다.

### 6. 쓰는 법

세션에서는 종목의 저장 실적과 근거를 요청한다. 새 공시가 필요할 때만 재무 갱신을 명시한다. 대시보드에서는 종목을 연 뒤 재무 탭에서 분기·연간 실적과 결측 이유를 확인한다. 두 입구의 이름·권한·갱신 버튼 동작은 M09·M10이 유지한다. Q3의 가설 검증일·반증 조건·검증 전 비중은 M05가 저장하며 M04가 실적 발표일을 수집하거나 자동 판정하지 않는다.

### 7. 사용자가 직접 확인하는 방법

5단계에서 M00이 제공하는 격리 검수 자료로 다음을 확인한다. 실제 공시 수집은 이 검수의 전제가 아니다.

1. 합성 미국·국내 종목의 같은 기간 실적을 열어 세션 결과와 재무 탭의 값·통화·기간·출처가 일치하는지 본다.
2. 일부 공시 수치가 없는 자료를 열어 빈칸의 이유가 보이고 0이나 예상 수치로 대체되지 않는지 본다.
3. 갱신 실패를 넣은 자료에서 실패 상태와 이전 성공 자료의 시각이 따로 보이는지 확인한다.

## 작업 지시서

### 1. 범위와 목표

**확정 범위:** M04는 조 2다. 조 0 M00의 격리 실행기와 조 1 M01의 정리가 합쳐진 기준에서 시작한다. M02·M03·M07·M08·M11과 병렬 작업하되 공유 파일을 수정하지 않는다. 분기·연간 실제 공시를 유지하며 C4의 교체 가능한 출처 경계만 만든다. 사용자 설명서 승인 전에는 구현하지 않는다.

**구현 제안:** `FinancialStore`의 공개 `read(key)`, `start(key, stock, refresh=False)`, `recalculate_saved(key, supplement=False, *, stock=None)` 호출 형식과 반환 필드를 유지한다. 생성자의 선택적 의존성 주입으로 출처 어댑터를 바꿀 수 있게 하고 기본값은 공식 출처 구현 하나다. 외부 서비스 선택 화면·설정 키는 추가하지 않는다.

어댑터의 내부 입력·출력은 다음 의미를 만족한다. 함수·자료형 이름은 아래 신규 파일 안에서만 정하고 공개 MCP/HTTP 형식으로 노출하지 않는다.

| 항목 | 구현할 계약 |
|---|---|
| 입력 | `key`(현재 `KR:…`/`US:…` 검증 유지), `period`(현행 수집 기간과 연간·분기 표시 범위), 작업용 원문 폴더·진행 보고 함수. 새 기간 선택 UI는 없음 |
| 기간 기본값 | 기존 `collect.py:101`의 현재 연도-6부터 현재, `normalize.py:390`의 보존 범위와 `calculate.py:106`의 연간 5개·분기 12개 표시를 그대로 전달. 비교용 앞선 기간을 표준화 이전에 잘라내지 않음. 새로운 임의 기간 수집 정책은 범위 제외 |
| 수집 결과 | 기존 `source` 원자료 묶음, `normalized` 표준 자료, `sources` 출처 목록을 함께 반환. `normalized.annual`·`quarterly` 행은 기존 `date,label,fy,fq,values` 형식을 보존 |
| 값과 출처 | 각 셀의 `value,unit,start,end,filed,sources,formula,reason` 및 기존 회계 범위·EPS 종류·재작성 이력 등을 보존. `sources` 항목의 `id,url,fetched_at,sha256,bytes`를 원바이트와 대응시킴 |
| 저장 자료 재계산 | 검증된 `source`·`sources`를 받아 같은 표준화 경로만 실행. `Collector`·인증·네트워크를 생성/호출하지 않음 |
| 명시 보완 | 기존 DART 보완 요청과 SEC 저장 재계산의 차이를 유지. 기존 발행회사 공식 IR PDF도 SEC/DART 어댑터에 포함(§8.4). 공급처별 보완을 저장 읽기에 섞지 않음 |
| 오류 | 기존 `SourceError`의 인증 부재·동일성 오류·전송 실패를 유지. 미지원 형식과 통신 실패를 합치지 않음. 값 부재는 기존 사유를 가진 셀, 수집 실패는 실패 상태로 처리 |

기존 `schema=2` 계산 결과, 계산/정규화 버전, `snapshot_id`, `source_snapshot_id`, `collected_at`, `recalculated_at`, `financial_as_of`, `data_quality`의 의미를 바꾸지 않는다. 출처 층 교체만으로 숫자 계산식·총주주환원 정의·지원 업종을 바꾸지 않는다.

### 3. 건드리면 안 되는 것

- M09 소유 `scripts/session_mcp.py`·`scripts/analysis/mcp.py`, M10 소유 `scripts/web/server.py`·`dashboard/shell/`, 공유 `config.json`, `scripts/market/daily.py`를 고치지 않는다. 분석·작도·감시·계좌 테이블과 `knowledge_*`를 쓰지 않는다.
- `scripts/records/store.py`·`files.py`·`paths.py` 등 공통 저장 API는 M03 소유다(§8.4). M04는 `records/financial.py`의 기존 게시 함수를 재사용하고 공통 저장 구현·스키마를 바꾸지 않는다. 다른 모듈의 쓰기 함수 호출과 같은 트랜잭션 사용은 C1이 허용한다.
- 가격 수집·OHLCV 쓰기 구현·`market/financial_price_receipts.py` 수정은 M03 범위다. M04는 M03의 `pack_price_input`·`price_input_bytes`·`read_price_input`을 재사용한다. 그 안의 `allow_variants=True` 과거 입력 보존을 없애거나 M04 자체 SQL·쓰기 경로로 옮기지 않는다.
- 실제 DB·runtime·원본 공시·보고서·과거 snapshot·개인 입력·사용자 방법론·`runtime/ma-dd-describe-20261017/raw`를 지우거나 덮어쓰지 않는다. 기존 자료 이동·정리는 M13이다.
- 인증 파일·키·토큰·실계좌번호를 읽어 fixture나 결과에 복사하지 않는다. 조회 전용 설정, 중지된 예약, 실제 Telegram을 건드리지 않는다. 운영 전환은 6단계다.
- 컨센서스·Forward 추정·LLM 숫자 보충·EPS 차감·결측 0 채움·ICR 복원·새 공급자 구독을 구현하지 않는다. 종료 기능·뉴스 보류·Q1~Q3 결정을 바꾸지 않는다.
- 현재 초안 작성 요청에서는 위 코드 수정뿐 아니라 시험 실행도 금지다. 아래 순서·명령은 설명서 승인 후 구현자에게 주는 지시이며 이번 수행 기록이 아니다.

### 4. 단계별 구현 순서

1. M00·M01이 반영된 기준에서 기존 변경을 보존한다. §8.4에 따라 공용 records API·가격 영수증은 M03 소유, 기존 공식 IR 보완은 C4 내부로 확정한다. M03과 기존 호출 서명·반환 및 오류 유지 여부를 대조하고 §8.2의 M00 실행기를 받는다.
2. 임시 root·합성 SEC/DART source·가짜 수집기를 준비하고 기존 표준화·계산 결과를 비교 기준으로 고정한다. 원문 수치·출처·해시는 fixture 안에서 직접 만든 값만 쓴다.
3. 공식 어댑터를 만들고 수집, 저장 source 표준화, 명시 보완을 분리한다. 기존 Collector·normalizer·business coverage·공식 IR PDF 보완을 재사용한다. 보완 없는 저장 재계산과 SEC의 기존 오프라인 재계산 동작을 유지하고, 알려지지 않은 provider를 SEC로 조용히 처리하지 않는다.
4. Store를 어댑터에 연결한다. 원문 → 표준화 → 계산 → 묶음 해시 → records 게시 → 최신 성공 포인터 순서를 유지한다. 게시/계산 실패 시 이전 성공 포인터를 유지하고 실패 시도만 기록한다. 과거 자료의 ID·해시·본문은 수정하지 않는다.
5. M03의 기존 가격 읽기·영수증 API와 `records/financial.publish_snapshot`을 재사용한다. `HistoryStore.view`의 가격 읽기 구현도 M03 소유다. 저장 재계산은 모든 입력 해시 검증 뒤 새 결과를 만들고, 현재 가격을 바꾸지 않는 과거 variant 참조를 보존한다. 가격 참조 오류·해시 불일치를 수집 재시도나 빈 성공으로 바꾸지 않는다.
6. `tests/suites/M04.txt`에 아래 필수 검사를 등록해 M00 실행기로 수행한다. M03 합친 뒤 API 호환·과거 가격 재현을 확인하고 M09·M10에 공개 호출 형식과 값/상태 예시를 인계한다. 실제 공급자·계좌 조회로 검사를 대신하지 않는다.

### 6. 검사 명령

§8.2의 M00 실행기 계약을 쓴다. M00이 고정한 개발 Python으로 WB에서 실행하며, 실행기 제공 뒤에만 수행한다. 이번 문서 개정에서는 실행하지 않는다.

.\.venv\Scripts\python.exe tests/run_isolated.py --module M04 --node test_financial_recalculate.RecalculateSaved.test_financial_variant_is_historical_only_and_reused

두 번째 명령은 가격 경계 부분 확인용이며 모듈 전체 통과를 대신하지 않는다. M04 소유 `tests/suites/M04.txt`에 다음 파일의 모든 TestCase 노드를 명시한다. 신규 어댑터 검사는 구현 때 만든 노드 ID로 등록한다.

- `test_financial_adapter.py`: AC04-01~03·06.
- `test_financial_actuals.py`, `test_financial_quality.py`: AC04-04.
- `test_financial_recalculate.py`, `test_financial_records.py`: AC04-05 및 과거 가격 재현.

영수증 JSON은 OS 임시 폴더에 둔다. 실패·차단·skip·미확인은 통과로 합산하지 않는다. 직접 unittest·전체 discovery, `financial.ps1`, `financial_summary.py`, 실제 DB의 `records/financial.py --verify`로 대체하지 않는다.
