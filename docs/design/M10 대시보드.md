# M10 대시보드

작성·개정: 2026-11-17 · 상태: **§8 반영 초안·설명서 승인 전** · 상세 설계 · 가정을 명시하면 설계 가능 / 설계 검토 가능

입력: [3단계 설계](<../3단계 설계.md>) 전체, **특히 §8(앞선 계약·순서보다 우선)**, [ver3.1](../투자에이전트ver3.1.md), [용어집](../용어집.md). `확정`은 상위 결정, `권장`은 구현안, `결정 필요`는 끝의 새 질문이다. 이번에는 문서·소스만 읽고 문서만 개정했다. 시험·서버·브라우저는 실행하지 않았다.

## 설명서

### 1. 하는 일

종목을 검색해 저장된 차트를 열고, 직접 선을 그리며 재무·분석·계획을 본다.
화면에 보이는 구간의 자동 L1 참고선과 감시·가격 위험 상태를 보여 준다.
후보 선별·계좌 현황 화면과 앱의 자동 계좌 조회를 걷어 낸다.

### 2. 입력과 출력

종목명·티커, 저장 자료, 사용자가 보는 차트 구간과 편집을 받는다. 차트·기록·저장 결과를 보여 주며 자료의 기준일과 없는 값을 구별한다. 자동선은 화면 이동이 멈추면 다시 계산하고, 최신 완료봉에 닿은 마지막 구간은 ‘진행 중’ 점선으로 표시한다. 자동선은 매매 신호가 아니다.

### 3. 저장 위치

M10이 직접 쓰는 업무 테이블은 없다. 화면은 워크벤치 `dashboard/`, 요청 전달은 `scripts/web/`에 둔다. 작도·분석·감시는 각 담당 모듈에 저장한다. 계좌 화면을 없애도 기존 계좌 관측과 분석에 필요한 보유 문맥은 남긴다.

### 4. 다른 모듈과의 연결

- **C1·§8.4:** 저장은 담당 모듈의 함수로 한다. 과거 사이클 테이블·데이터는 보존한다.
- **C2·C4:** 가격은 M03, 재무는 M04의 읽기 결과를 표시한다.
- **C3·§8.1:** 작도·자동 L1 계산과 차트 조각은 M06, 이를 세션에서 읽는 도구는 M09가 제공한다.
- **C5·§8.1:** 보유 종목의 가격 위험은 자동 감시하고, 미보유 기술 신호·시나리오는 명시 등록만 한다. 저장 관측의 기준 시각을 보여 준다.
- **C6·C7·§8.3:** 조 1에서 M01이 종료 참조를 먼저 제거한다. 조 2부터 MCP는 M09, HTTP·셸은 M10이 맡는다.
- **C8·§8.2:** 실제 자료와 외부 연결 없이 M00의 합성 자료로 검사한다.

### 5. 이번 개편에서 바뀌는 것 / 그대로인 것 / 없어지는 것

| 구분 | 내용 |
|---|---|
| 바뀜 | 검색에서 차트로 진입한다. 자동선을 L1 참고선으로 바꾸고, 계획의 가설 검증일·반증 조건·검증 전 비중을 보여 준다. 세션으로는 문맥을 복사해 넘긴다. |
| 그대로 | 직접 작도·재무·분석/논의·계획·시나리오 감시·가격 위험 경고, 자료 기준일·저장 충돌 안내·사용자 채택 절차. |
| 없어짐 | 홈 후보·스크리닝·섹터·매매 사이클·계좌 현황 화면, 자동 계좌 조회, Codex 실행 링크와 옛 자동 추세선의 사용. |
| 범위 제외 | 뉴스 개편, EPS 수집, 자동 가설 판정, 실제 알림·주문·예약 재개. |

### 6. 쓰는 법

종목 검색 → 차트에서 직접 작도 → 재무·분석·계획 확인 순서로 쓴다. 차트를 옮기거나 확대하면 보이는 구간의 L1 참고선이 바뀐다. 세션에서 이어 보려면 ‘문맥 복사’를 눌러 대화에 붙여 넣는다. 계좌 확인은 세션의 공식 MCP로 하며 대시보드는 마지막 저장 관측을 사용한다.

### 7. 사용자가 직접 확인하는 방법

5단계의 격리된 합성 화면에서 ① 저장 종목 검색·작도 저장/재열기를 확인한다. ② 화면 이동·시간틀 변경 때 자동선과 계산 구간이 맞는지 본다. ③ 재무 출처·계획 세 칸·가격 및 관측 시각을 읽는다. ④ 종료 메뉴·앱 실행 링크가 없고 문맥 복사는 되는지 본다. ⑤ 저장 충돌과 자료 없음이 구별되는지 본다. 실제 대시보드 확인은 뒤의 운영 적용에서 한다.

## 작업 지시서

### 1. 범위와 목표

**확정:** 조 4, M09와 병렬. M00→M01→조 2→M05→M06을 인계받는다. M01은 조 1에서 공유 파일의 종료 참조만 제거하고, M10은 그 결과에 새 화면 연결을 구현한다(§8.3). M09의 MCP 파일은 고치지 않는다.

**권장:** 첫 화면은 `#search`. 기존 `#stock/{market}/{symbol}`, `?analysis=...`, `#risk`를 유지한다. 빈 주소와 종료한 `#home/#screen/#sectors/#sector/#focus/#cycles/#cycle/#accounts/#account`는 검색 안내로 보낸다. `/api/home`은 남겨 시장 기준일·품질·상태만 투영하고 계좌 목록·선별 결과는 제외한다. 내부 저장 계좌 문맥은 M05/M07을 위해 보존하며 `generated_at`을 가격·잔고 시각으로 부르지 않는다.

**자동 L1 연결(§8.1):** M06이 저장 일봉을 읽어 화면의 일·주·월 완료봉 구간으로 계산한다. M10은 구간 시작·끝·시간틀을 받는 읽기 전용 GET을 연결한다(**권장 경로:** `/api/l1-trendlines/<종목키>`). 결과·계산 구간·상태를 그대로 반환하고 저장·수집·작도 채택·감시를 호출하지 않는다. 화면 이동이 멈춘 뒤 짧은 지연을 두고 한 번 요청하며 오래된 응답은 버린다. 선 그리기·기울기·봉 집계는 M06 조각/함수에 맡긴다. 자동선은 사용자 작도와 별도이며 최신 완료봉에서 끝나는 마지막 구간만 ‘진행 중’ 점선이다. 옛 `screening.trendlines` 사용은 종료하되 코드 이관 충돌은 M10-Q06에 남긴다.

**계좌(§8.1·§8.6):** M08은 앱의 직접 조회 코드를 제거하고 저장 관측 함수를 제공한다. M10은 `web/server.py`·`web/data.py`·`web/refresh.py`에서 시작/갱신이 계좌 조회를 요구하는 연결을 제거하고 마지막 저장 관측만 읽는다. 가격 위험은 M07 결과와 관측 기준 시각을 표시한다. M12는 조 5에서 `launch/daily.py`·`scheduled.py`의 `accounts=True`·전송 결합과 시작 메뉴를 정리한다. M10이 실행기 파일이나 전송 정책을 대신 고치지 않는다.

M05가 제공하는 `dashboard/analysis/analysis.js`·`collaboration.js`의 문맥 복사·계획 세 칸을 장착한다. 검증 전 비중은 분모 포함 원문 문자열이며 숫자로 환산하지 않는다. 새 앱 URI·자동 가설 판정·실적일 수집·주문은 추가하지 않는다.

### 3. 건드리면 안 되는 것

- M09 MCP 파일·도구 이름/인자, 각 서비스 폴더·테이블과 M04~M07 소유 화면 조각. M10에 SQL·스키마·저장 우회 경로를 만들지 않는다.
- `config.json`, `market/daily.py`, `launch/`, PS1·예약·인증·MCP 설정. 필요한 변경은 §8의 담당 모듈에서 받는다.
- 기존 계좌 관측·원본·DB·확정 계획·과거 snapshot·MA 원시입력 8,851파일. 종료 화면을 지운다고 기록을 지우지 않는다.
- 뉴스 코드·화면·의존성은 보류. 종료 사이클·옛 위험/보호 계산을 되살리지 않는다.
- 주문·환전·조회 전용 해제·실제 계좌/Telegram/시장 수집/예약 재개는 금지. 키·토큰·실계좌번호를 HTTP·화면에 넣지 않는다.
- 이번 문서 개정에서는 코드·설정·DB·runtime·STATUS·DECISIONS·3단계 설계 수정, 시험 실행, 네트워크, 커밋을 하지 않는다.

### 4. 단계별 구현 순서

1. **인계 확인:** M00 실행기·M01 종료 정리·M03/M04 읽기·M05 문맥 복사/계획·M06 작도/L1·M07 경고·M08 저장 관측을 받는다. M10-Q06의 옛 자동선 파일 처리와 M06 계산 미결은 확인 전 임의 구현하지 않는다.
2. **셸 축소:** 종료 메뉴·분기·자산을 걷고 검색 첫 화면과 기존 종목·분석 ID를 연결한다. M05 문맥 복사 조각을 사용해 URI 실행을 없앤다.
3. **HTTP·자동선 연결:** 읽기 전용 L1 요청을 M06에 전달하고 화면 구간·시간틀·응답 최신성 처리를 제공 조각과 맞춘다. 기존 검색·재무·작도 요청의 검증을 보존한다.
4. **계좌·상태 연결:** 웹 시작/갱신에서 자동 계좌 조회 요구를 제거한다. 저장 관측과 가격의 시각, 결측·실패·충돌을 구별한다. M12에는 실행기·시작 화면 변경을 인계한다.
5. **격리 검사:** M10 선택 목록과 아래 검사를 M00으로 실행한다. 합성 화면 검수 근거를 남기며 운영 대시보드 실행으로 대체하지 않는다.

| 시작·갱신 | 계좌 조회를 요청하지 않는다. 시장 갱신은 기존 명시 실행 정책을 따르며 계좌 실패를 시장 재시도로 바꾸지 않는다. |
| 변경 요청 | Host·Origin·token·확인 cookie·JSON·본문 크기 검사 유지. 잘못된 origin 403, JSON 아님 415, 과대 본문 413. |
| offline | 외부 갱신은 차단하지만 작도·분석 저장은 가능하다. DB 무변경 모드라고 안내하지 않는다. |

### 6. 검사 명령

§8.2 확정 규약이다. 구현 승인 후 WB에서 M00의 독립 Python으로 실행한다. **이번 개정에서는 실행하지 않는다.**

```powershell
.\.venv\Scripts\python.exe tests/run_isolated.py --module M10
```

선택 목록은 **`tests/suites/M10.txt`**다. `test_dashboard_v3_contract.py`의 AC01~08 대응 노드, `test_stock_search.SearchIndex`, guard 안으로 옮긴 `test_dashboard.HttpBoundary`·`test_stock_search.SearchHttp`의 필요한 HTTP 노드, `tests/test_dashboard_v3_shell.cjs`·`tests/test_stock_search.cjs`를 등록한다. 개별 재검사는 같은 명령에 `--node 노드ID`를 붙인다. Python·Node·fixture 자식 프로세스는 import 전 같은 guard를 적용한다.

메모리 Handler/가짜 DOM·fetch를 우선 쓰고 HTTP 경계는 OS 임시 합성 workspace의 127.0.0.1·socketpair로 검사할 수 있다. 운영 서버에는 연결하지 않는다. 결과 JSON은 OS 임시 폴더에 남긴다. M00 실행기나 선택 목록이 미구현이면 완료 판정을 보류하며 직접 unittest/Node 또는 실제 대시보드 실행으로 대신하지 않는다.
