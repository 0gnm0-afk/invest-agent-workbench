# M08 계좌 관측

작성: 2026-11-17 · DESIGN-3-20261117 · **§8 반영 개정안·사용자 승인 전** · 조 2

상세 설계 / 설계 검토 가능. [3단계 설계](<../3단계 설계.md>) §8을 이전 계약·초안보다 우선한다. `확정`은 §8의 결정·기존 보존 계약, `권장`은 구현 방법, `결정 필요`는 남은 질문이다. 이번 개정은 문서만 다루며 시험·계좌·DB·MCP를 실행하지 않았다.

입력: 3단계 설계 전체(특히 §8.1·§8.2·§8.4~§8.6), [기능 목록](<../2단계 기능 목록 초안.md>), [기술부채 진단](<../2단계 기술부채 진단.md>), [ver3.1](../투자에이전트ver3.1.md), [용어집](../용어집.md).

## 설명서

### 1. 하는 일

세션에서 공식 MCP로 조회한 NH·메리츠 계좌 결과를 당시 시각과 함께 보관한다.
실패하거나 덜 끝난 조회를 정상적인 빈 잔고와 구별한다.
분석·감시에는 마지막 저장 관측과 그 기준 시각을 제공한다.

### 2. 입력과 출력

| 입력 | 출력 |
|---|---|
| 증권사와 조회 요청 ID | 새 조회 가능 여부, 진행 중이거나 완료된 요청 |
| 실제 응답·조회 시각·페이지 완료 근거 | 보유·통화·관측 금액, 전체/부분/실패 상태 |
| 저장 결과 조회 | 증권사별 당시 관측값·시각, 최근 시도의 상태와 한계 |

조회 중인 요청에만 완료 권한을 주는 값이 `lease`다. 같은 요청으로 중복 조회하지 않으며, 예수금만 보고 미체결·부채까지 확인됐다고 표현하지 않는다.

### 3. 저장 위치

`runtime/accounts.sqlite3`의 `account_objects`에 관측 결과, `account_queries`에 요청·완료 상태를 둔다. 쓰기 함수는 M08이 소유한다(C1·§8.4). 날짜별 DB 사본을 만들지 않는다. 세션 표시에는 계좌번호·인증값·원응답을 제외한다.

### 4. 다른 모듈과의 연결

- **C1·§8.4:** 다른 모듈은 M08의 저장·조회 함수를 사용한다. 기존 관측과 참조를 보존한다.
- **C5·§8.1:** M07의 보유 종목 가격 위험 경고는 자동 감시한다. 기술 신호·시나리오는 명시 등록하며, 매수 시나리오를 보유 감시로 자동 전환하지 않는다.
- **C6·§8.6:** 새 계좌 MCP는 노출하지 않고 `record.py` 저장 CLI를 유지한다. M08이 세션 표시용 함수를 제공하고 M05가 조 3에서 연결한다.
- **C7·§8.6:** 계좌 화면 제거는 M10, 실행기의 자동 조회·전송 결합 제거는 M12가 맡는다.
- **C8·§8.2:** 구현 검사는 M00 실행기와 가상 계좌 자료로만 한다. 실제 환경 확인은 별도 운영 적용이다.

### 5. 이번 개편에서 바뀌는 것 / 그대로인 것 / 없어지는 것

- **바뀜:** 계좌는 세션에서 조회한다. 필요한 경우 계좌번호를 뺀 Claude 아티팩트로 본다. 경고·감시는 저장 관측의 기준 시각을 표시한다.
- **유지:** NH·메리츠 저장, 조회 시각·완전성·요청 잠금, 실패와 이전 성공 관측의 구별. 저장값을 현재 잔고라고 부르지 않는다.
- **없어짐:** 앱의 직접 NH 조회와 워크벤치 계좌 화면. Telegram 전송은 계좌 조회 여부와 분리한다. 기존 관측 데이터는 보존한다.

### 6. 쓰는 법

세션에서 증권사를 밝히고 계좌를 조회하거나 “이전에 저장한 계좌 상태와 조회 시각”을 요청한다. 새 조회는 `begin`으로 중복 여부를 확인한 뒤 공식 MCP 결과를 `complete`로 저장한다. 대시보드 시작이나 아침 실행이 계좌를 자동 조회하지 않는다.

### 7. 사용자가 직접 확인하는 방법

가상 계좌 자료에서 ① 증권사별 관측 시각, ② 실패해도 바뀌지 않는 과거 잔고 시각, ③ 페이지 누락의 부분 표시, ④ 같은 요청의 중복 조회 방지, ⑤ 세션 결과의 계좌번호·인증값·원응답 제외를 확인한다. 실제 DB·대시보드 확인은 뒤의 운영 적용 항목에서 별도로 한다.

## 작업 지시서

### 1. 범위와 목표

**확정(§8.1·§8.6):** M00의 격리 실행기·계좌 경계 fixture 갱신, M01 종료 기능 정리 뒤 조 2에서 작업한다. `accounts/__init__.py`의 앱 NH 직접 조회 경로를 제거하고 저장·완전성·lease·`record.py` CLI를 유지한다. `accounts/mcp.py`는 파일만 보존하고 노출하지 않는다. M08은 세션 표시용 허용 필드 함수를 제공하고 M05가 조 3에서 감싼다. 계좌 UI는 M10, `launch/daily.py`·`scheduled.py`의 `accounts=True`와 전송 결합은 M12가 조 5에서 제거한다.

**권장 구현:** `accounts/saved.py`에 `ReadOnlyAccountStore`, `saved_accounts(root)`, `session_projection(view)`를 둔다. 현재 `analysis/direct_accounts.py`의 읽기 구현을 기준으로 `mode=ro`·`PRAGMA query_only=ON`, 파일 부재 시 `missing`, `merge_saved(..., persist=False)`를 유지한다. `accounts, as_of, attempted_at, query_state, reason, source_mode, stale, accounts_complete, limitations`와 증권사별 관측·환율의 의미를 보존한다.

내부 관측의 `positions[].lots`와 저장 원본은 그대로 둔다. 세션 표시용 함수는 필요한 정규화 필드만 새 객체로 고른다. 허용 범위는 증권사·안전한 계좌 alias, 종목·시장·수량·관측 가격·평균단가·통화, 관측 시각·최근 시도 시각·상태·완전성·결측 이유, 정규화된 현금/관측 금액·증권사별 환율이다. 기존 숫자 문자열 정밀도를 유지한다. `lots/broker_lot`, 원응답과 raw 참조, 계좌번호·인증·lease는 어느 중첩 위치에서도 반환하지 않는다. 자유 형식의 원문을 정규화 필드로 우회 전달하지 않는다. 구체적 키 목록과 오류·누락 기대값은 기존 정규화 구조를 기준으로 A08-05·06 fixture에 고정해 M05에 인계한다.

저장·조회 계약은 다음과 같다.

| 진입점 | 입력·출력 및 유지할 규칙 |
|---|---|
| `AccountStore.begin(provider, request_id, origin)` | provider=`nh|meritz`, origin=`api|mcp`, request_id 1~200자. 새 요청만 `execute=True,lease`; 같은 요청 또는 같은 증권사 pending은 `execute=False`. 시간만으로 pending을 만료·재조회하지 않음 |
| `normalized(provider, observation)` | 시간대가 있는 `as_of`, 계좌 alias, NH 실제 페이지·업무 메시지·종료 header 또는 메리츠 응답·연속키를 검증. 기존 schema·숫자 문자열 정밀도 유지 |
| `AccountStore.complete(...)` | 정확한 lease와 `query_state=received|partial|failed`. received/partial은 snapshot 필수. failed를 성공으로 꾸미지 않고 snapshot_ref/raw_ref·attempted_at 보존 |
| `latest(provider)` / `latest_attempt(provider)` | 최근 관측과 최근 완료 시도를 별도로 반환. 실패를 빈 보유나 신규 성공 시각으로 바꾸지 않음 |
| `saved_accounts(root)` | 저장 관측만 결합. 외부 조회·저장·export 없이 증권사별 시각·완전성·환율 유지. 외부 표시 전에 `session_projection` 적용 |

NH `nh_success`·페이지 연결·종료 근거와 메리츠 `meritz_next` 완료 근거를 유지한다. `received`는 보유 관측의 상태이며 모든 자산이 완전하다는 뜻이 아니다. `cash_complete`, `holdings_complete`, `accounts_complete`, 미지원 자산·결측 이유와 기존 24시간 기준을 바꾸지 않는다.

### 3. 건드리면 안 되는 것

- `analysis/*`, `session_mcp.py`, `accounts/mcp.py` 도구 정의, `web/*`, `dashboard/shell`, `launch/*`, `config.json`, PowerShell 실행기·예약은 각 담당 모듈에 인계한다.
- 다른 모듈 테이블, 기존 계좌 객체·요청 이력·원응답 참조·과거 snapshot·계획·원본 공시·방법론·보호 원자료는 보존한다. `trade_cycle*`도 테이블과 데이터를 그대로 둔다(§8.4).
- 주문·환전·조회 전용 해제·계좌 자동 재시도·pending 자동 해제·잔고로 체결 추정을 하지 않는다. `MERITZ_READ_ONLY=1`, `NHPLUG_ENABLE_TRADING=false` 유지.
- 실제 키·토큰·계좌번호를 로그·문서·HTTP·아티팩트에 내보내지 않는다. 인증 경로·파일·Windows 사용자 환경변수를 읽거나 바꾸지 않는다.
- 루트 `nh_api`·`nh_master`·Toss helper는 이 모듈에서 삭제하지 않는다. §8의 남은 질문을 먼저 처리한다. 공식 NH MCP가 사용하는 `nh_auth`는 보존한다.
- 구현 검사는 OS 임시 workspace만 사용한다. 실제 runtime·DB·대시보드·Telegram·계좌·예약 작업은 구현 범위 밖이다. 이번 문서 개정에서는 모든 시험 실행도 금지한다.

### 4. 단계별 구현 순서

1. M00의 `tests/run_isolated.py`·BrokerBoundary 갱신 결과와 M01 통합 결과를 받는다. `tests/suites/M08.txt`를 작성하고 아래 검사만 등록한다.
2. 기존 `begin → execute=True일 때만 공식 조회 → normalized → complete` 계약을 합성 입력으로 고정한다. 정규화 실패가 `failed/broker_normalization_failed`로 끝나는 동작을 유지한다. 시험에서 공식 MCP를 호출하지 않는다.
3. `accounts/saved.py`에 읽기 전용 저장 관측과 세션 표시용 함수를 만든다. 읽기에서 기본 쓰기 connect·스키마 생성·WAL 설정·객체 저장을 호출하지 않는다. 없는 DB는 `missing`, 읽기 실패는 오류로 구별한다.
4. `accounts/__init__.py`의 직접 NH 호출·루트 adapter import를 제거한다. 순수 검증 helper는 유지할 수 있다. 후속 모듈이 아직 사용하는 `account_view`·`refresh_account_snapshot` 이름을 남기는 경우에는 저장 조회로만 위임하고, `refresh=True`도 begin·브로커·DB 쓰기를 유발하지 않게 한다. 과거 관측을 새 조회 성공으로 바꾸지 않는다.
5. 내부 원 lot 보존과 외부 허용 필드 변환을 검사한다. 직접 NH 조회를 기대하던 기존 시험은 합성 저장 결과로 바꾼다. M05에 반환·오류·누락 fixture, M07에 기준 시각/partial 판정, M10·M12에 호환 진입점과 제거할 호출 목록을 넘긴다. 다른 모듈 파일은 대신 고치지 않는다.
6. §8.5에 따라 M03과 루트 helper 잔여 참조를 정적으로 대조한다. NH 2개는 Q-M08-05, Toss 3개는 M03 Q6으로 종료 여부를 인계하며 판단 전 삭제하지 않는다.
7. §6의 M00 실행기로 완료 기준을 확인한다. M05 연결은 조 3, M10 화면 제거는 조 4, M12 실행기 연결은 조 5의 후속 통합으로 구분한다.

### 6. 검사 명령

§8.2의 M00 실행기 계약을 사용한다. 아래는 구현 뒤 실행할 명령이며 이번 문서 개정에서는 실행하지 않는다.

```powershell
# 작업 위치: WB
.\.venv\Scripts\python.exe tests/run_isolated.py --module M08
```

모듈 소유 선택 목록 `tests/suites/M08.txt`:

```text
test_account_store.AccountStoreTests
test_broker_accounts.BrokerContracts
test_broker_accounts.SavedProviderIntegration
test_account_observation_contract.AccountObservationContractTests
```

필요한 개별 검사도 같은 실행기에 `--node 노드ID`를 붙인다. 영수증 JSON은 OS 임시 폴더에 남기며 가드 사건·차단·skip·미확인을 별도 확인한다. 실행기를 거치지 않는 `unittest`·`pytest`·앱 실행으로 대체하지 않는다.

CLI 검사는 `record.main`에 가짜 AccountStore·argv·stdin/stdout를 주입한다. 운영 경로의 `record.py begin/complete`, MCP 서버·증권사 도구·대시보드·예약·DPAPI는 실행하지 않는다. M00 BrokerBoundary 결과는 선행 증거, M05의 저장 계좌 소비 검사는 조 3 후속 증거다.
