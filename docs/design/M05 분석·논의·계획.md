# M05 분석·논의·계획

작성: 2026-11-17 · 상태: **초안·§8 반영·사용자 승인 전** · 상세 설계 개정 · 판정: 설계 가능 / 설계 검토 가능

입력: [3단계 설계](<../3단계 설계.md>) 전체(특히 **§8 우선**, §6 Q3·§7), [DESIGN-3-20261117](../../DECISIONS.md#design-3-20261117), [SELECT-2-20261117](../../DECISIONS.md#select-2-20261117), [기능 목록](<../2단계 기능 목록 초안.md>), [기술부채 진단](<../2단계 기술부채 진단.md>), [ver3.1](../투자에이전트ver3.1.md), [용어집](../용어집.md).

`확정`은 위 입력에서 정한 범위, `권장`은 이 초안의 구현안, `결정 필요`는 끝의 열린 질문이다. 코드 줄은 2026-11-17 정적 열람 기준이며 선행 모듈을 합친 뒤 다시 대조한다. 이번 개정은 문서만 다루며 코드·설정·DB·runtime 변경, 시험·앱·외부 연결 실행은 하지 않는다.

## 앞 절반 — 설명서

### 1. 하는 일

종목별 분석 자료와 보고서, 사용자와 나눈 논의, 계획의 변경 과정을 보존한다.
계획에 가설을 확인할 실적 발표일·반증 조건·검증 전 비중을 남긴다. 비중은 기준을 포함한 사용자 문장 그대로 보존한다.
초안과 사용자가 채택한 정확한 버전을 구별해 다음 세션과 감시에 전달한다.

### 2. 입력과 출력

| 입력 | 출력 |
|---|---|
| 종목·분석건, 저장 당시 가격·재무·작도·보유 문맥 | 당시 입력 묶음(snapshot)과 그 식별자·기준일 |
| 실제 발언, 자료 근거, AI 해석, 미정 질문 | 작성 주체와 원문 연결을 보존한 논의 기록 |
| 계획 내용과 세 가지 가설 기록 칸 | 이전 내용을 덮지 않는 새 계획 버전 |
| 사용자의 화면 확인 | 정확한 버전의 채택·해제 기록. 실제 주문·체결과는 별개 |

snapshot은 당시 자료를 고정한 묶음이고, revision은 동시 수정을 감지하는 번호다. 계획 내용의 버전과 다른 값이다. 모듈 사이 약속은 [인터페이스 계약](../용어집.md), 사용자가 결과를 확인하는 절차는 [인수 검수](../용어집.md)를 따른다.

### 3. 저장 위치

`확정` — 워크벤치 `runtime/chart-workspaces.sqlite3`의 `analysis_cases`, `analysis_snapshots`, `analysis_snapshot_inputs`, `analysis_items`, `analysis_collaboration_heads`를 M05가 쓴다. 계획·논의·채택은 `analysis_items` 안에서 종류로 구별한다. 사람이 읽는 파일은 기존 `judgments/analyses/<분석건>/<기록>.md`에 둔다. 지식 원문은 M02, 작도는 M06, 계좌 관측은 M08의 저장 책임이다.

### 4. 다른 모듈과의 연결

아래는 [3단계 설계 §8](<../3단계 설계.md>)을 우선 반영한 연결 약속이다.

| ID | M05가 지킬 약속 |
|---|---|
| C1 · §8.4 | M05는 분석 기록을 맡는다. 다른 저장소는 담당 모듈의 함수로 쓰며, 계획 채택과 작도 저장을 한 번에 처리하는 기존 방식은 유지한다. 사이클 테이블·데이터는 보존한다. |

| C5 · §8.1 | 보유 종목의 가격 위험은 자동 감시한다. 기술 신호와 미보유 종목 시나리오는 명시 등록하며, 이전 계획·작도 참조는 보존한다. |

| C8 · §8.2 | M00 실행기로 합성 자료만 검사한다. 실제 자료 확인은 별도 운영 적용이다. |

### 5. 이번 개편에서 바뀌는 것 / 그대로인 것 / 없어지는 것

- **바뀜(확정):** 계획에 `가설 검증일(실적 발표일)`, 정성 문장 그대로의 `반증 조건`, `검증 전 비중`을 저장·조회한다. 작도 설명은 M06에서 받아 당시 입력과 최신 설명을 구별한다. 새 조사 안내는 `eps-research`를 가리키고, 세션에 붙여 넣을 문맥 복사만 남긴다.
- **유지(확정):** 원문·과거 snapshot·보고서·계획 버전·사용자 채택·충돌 방지·저장 재확인. 새 초안이 이전 채택 버전을 바꾸지 않는다.
- **없어짐(확정):** M01이 제거한 36조합 매매 사이클과 옛 위험 계산을 다시 연결하지 않는다. 가설 검증일 자동 수집·반증 자동 판정·비중 자동 계산·주문은 범위 밖이다. 뉴스는 보류 상태를 유지한다.

### 6. 쓰는 법

**세션에서:** 기존 논의와 정확한 채택 버전을 먼저 읽고, 필요할 때만 현재 저장 입력을 고정한다. 실제 발언·근거와 가설 기록 세 칸을 계획 초안에 남기며 모르는 값은 미정으로 둔다. 저장 결과의 ID·버전·재조회 일치를 확인한다.

**대시보드에서:** 종목의 분석·논의 패널에서 보고서와 초안·채택 버전을 읽는다. 세 칸을 포함한 정확한 버전을 확인한 다음 채택하거나 해제한다. 화면 연결은 M10이 맡는다. 계좌 화면 제거와 관계없이 저장 당시 보유 문맥과 그 기준 시각은 유지한다.

### 7. 사용자가 직접 확인하는 방법

5단계에서 격리된 합성 종목으로 다음을 확인한다. 실제 자료를 쓰는 확인은 뒤의 운영 적용으로 분리한다.

1. 논의와 계획을 저장하고 다시 열어 원문·세 칸·자료 기준일이 그대로인지 본다.
2. 계획 1판을 채택한 뒤 2판을 초안으로 저장한다. 채택 표시가 1판에 남고, 2판을 직접 채택해야 바뀌는지 본다.
3. 작도를 수정한 뒤 과거 계획의 좌표·참조 번호가 그대로이고 최신 작도 설명과 구별되는지 본다(M06·M10 통합 뒤).
4. 다른 창에서 먼저 수정한 뒤 낡은 버전으로 저장하면 덮어쓰지 않는지, 복사한 문맥으로 같은 분석건의 논의를 이어갈 수 있는지 본다.

## 뒤 절반 — 작업 지시서

### 1. 범위와 목표

`확정` — **조 2b에서 C2 소비 경계 전환, 조 3에서 M05 → M06**. M00·M01과 조 2의 M03·M08·M11 인계가 선행한다. M03 병합 뒤 `direct.py`의 직접 일봉 SQL을 공개 읽기로 바꾸고, 조 3에서 기록 확장·M08 표시 함수 래퍼·M06 참조 서비스를 제공한다. M09·M10은 조 4에서 도구·화면을 연결한다. M07의 조 2 구현에는 새 필드를 선행 요구하지 않는다.

대상은 분석건, 불변 snapshot, 보고서, 논의, 계획 버전·채택, Q3 세 칸, M06에 넘길 채택 계획 참조다. `analysis_key → snapshot_id → plan_record_id/plan_id/plan_version`과 `drawing_id/workspace_revision`을 유지한다. 지식 검색·조사 수행, 가격·재무·계좌 갱신, 감시 등록·판정·전송은 제공 모듈 책임이다.

**권장 계획 확장안(기존 저장 계약의 부가 필드):** `plan.hypothesis`를 선택 객체로 추가한다. 새 객체가 있으면 아래 세 키만 허용한다. 기존 `collaboration.v1`의 envelope와 인자 이름은 유지하며 M09에 이 객체의 검증·조회 형식을 인계한다. 기존 계약 문서는 부가 필드를 허용한다(`docs/collaboration-contract-v1.md:13`). 호환되지 않는 요구가 생기면 임의 버전 변경 대신 M09와 다시 검토한다.

| 저장 키(권장) | 표시명·형식 | 검증·보존 |
|---|---|---|
| `verification_date` | 가설 검증일(실적 발표일), `YYYY-MM-DD` 또는 null | 기존 `day()` 방식의 실제 달력 날짜 검증. 미래·과거 날짜의 업무적 적합성은 자동 판정하지 않음 |
| `invalidation_statement` | 반증 조건, 문자열 또는 null | 최대 12,000자. 줄바꿈·정성 표현 그대로 보존. 숫자 조건으로 변환하지 않음 |
| `pre_verification_allocation` | 검증 전 비중, 문자열 또는 null | 최대 4,000자(권장 제한). 사용자에게 분모를 함께 적게 안내하고 원문으로 저장(§8.5 확정). 수량·현금·분모를 추론하거나 기존 `allocation`에 환산하지 않음 |

기존 계획은 객체가 없어도 유효하다. 화면에서만 세 칸을 `미정`으로 표시하고 저장된 JSON·plan_sha256·Markdown을 재작성하지 않는다. 새 계획에 세 칸이 없어도 저장을 허용한다. 별도 자동 판정·채택 차단 조건을 추가하지 않는다. 내용을 바꾸면 기존 `plan_save`로 새 버전을 만든다.

**유지할 서비스 계약:** `discussion_save`/`plan_save`의 공통 입력은 `contract_version`, `analysis_key`, `snapshot_id`, `expected_revision`, `references`다. 계획은 여기에 `plan_id`(새 계획은 null), `expected_plan_version`(새 계획은 0), `plan`을 받는다. 성공은 `{contract_version, revision, record, verified: true, links}`이고, DB 재조회·Markdown 해시 확인 뒤에만 반환한다. 낡은 revision/version은 충돌로 돌려주고 자동 재시도·병합하지 않는다. 사용자 발언과 자료 주장은 references의 `speaker`로 구별한다.

**M06 인계(권장):** `Collaboration.plan_basis(cid, rid, require_adopted=True)`의 정확한 버전 검증을 재사용하는 읽기 전용 종목별 참조 서비스를 제공한다. 입력은 정확한 `stock_key`, 명시한 임시/운영 저장소 문맥이다. 출력은 `analysis_key`, `plan_record_id`, `plan_id`, `plan_version`, `plan_sha256`, `snapshot_id`, `snapshot_sha256`, 채택 기록 ID, 종목 동일성, 원 `drawing_ref` 목록과 해당 고정 작도 근거다. 전체 기록에서 유효한 채택 결정을 적용하고, 최신 초안을 채택으로 간주하지 않는다. 읽기 전용 연결과 snapshot reader를 주입하며 생성자 초기화·capture·계좌 저장·작도 자동 이전을 호출하지 않는다. 누락·무결성 실패는 근거 없는 빈 성공으로 바꾸지 않는다. C3 최신 해석 자체는 M06에서 만들며 M05가 기하 계산을 복제하지 않는다. C3는 최신 공유 작도와 채택 계획의 정확한 revision을 따로 반환하고, 채택하지 않은 AI 제안은 제외한다. 비교는 저장된 최신 완료 일봉 종가·날짜, 거리 `종가 − 선값`과 비율 `(종가 − 선값) / 선값 × 100`을 사용한다. 작도의 시간틀(없으면 일봉)과 `workspace_saved_at`을 유지한다. 자동 L1 추세선은 §8.1의 별도 참고 묶음이며 계획 채택·감시 근거로 자동 편입하지 않는다. `investment_context` 결합은 조 4의 M09가 맡는다.

**확정 계좌 경계(§8.1·8.6):** `analysis/direct_accounts.py`는 M08 저장 읽기와 세션 표시용 허용 필드 함수의 호환 래퍼로 바꾼다. M08의 정규화된 값·관측 시각·완전성·실패 의미를 보존하고 원 lot·원응답·계좌번호·인증·lease는 반환하지 않는다. snapshot의 기존 `AccountStore.save`는 M08 소유 함수에 맡기는 내용 해시 기반 입력 보존이며, 새 계좌 조회·관측 완료 기록으로 취급하지 않는다. 계좌 관측 생성은 세션 조회 결과의 `record.py begin/complete`만 따른다. 과거 snapshot의 원문·해시는 바꾸지 않는다.
