# M02 지식

작성: 2026-11-17 · DESIGN-3-20261117 · **초안·사용자 승인 전** · 조 2

상세 설계 개정 / 설계 가능·설계 검토 가능. [3단계 설계 §8](<../3단계 설계.md>)을 앞선 계약보다 우선한다. 기존 질문 3개는 결정 반영, 남은 질문은 없다. 설명서는 사용자 승인 전이며 시험·운영 실행은 하지 않았다.

입력: [3단계 설계](<../3단계 설계.md>) 전체, [DESIGN-3](../../DECISIONS.md#design-3-20261117)·[SELECT-2](../../DECISIONS.md#select-2-20261117), [기능 목록](<../2단계 기능 목록 초안.md>), [기술부채 진단](<../2단계 기술부채 진단.md>), [ver3.1](../투자에이전트ver3.1.md), [용어집](../용어집.md). 코드 근거는 2026-11-17 정적 열람 기준이며 실행 결과가 아니다.

## 설명서

### 1. 하는 일

자료 원문, 사용자가 한 말, AI가 정리한 생각을 구별해 쌓는다.
새 대화에서 관련 자료·이전 생각·풀리지 않은 질문을 찾아 논의를 이어 준다.
지금의 키워드 검색을 나중에 바꿀 수 있게 내부 연결을 정리한다([지식 베이스·에이전트 메모리, 리팩터링](../용어집.md)).

### 2. 입력과 출력

| 입력 | 출력 |
|---|---|
| 사용자가 준 글·파일, 출처·기준일, 종목·주제 | 저장 ID, 원문 확인값, 저장·재조회 확인 결과 |
| 실제 발언과 말한 주체, 수정하거나 해결한 이전 기록 ID | 원래 기록을 남겨 둔 새 기록 |
| 종목·주제·검색어 | 원자료와 발언 미리보기, 전문을 여는 ID, 다음 페이지, 관련 주제·미정 질문 |
| 근거 ID와 직전 요약 번호 | 새 AI 요약과 이전 요약 이력. 사용자 채택을 뜻하지 않음 |

### 3. 저장 위치

`runtime/records.sqlite3`의 `knowledge_blobs`, `knowledge_sources`, `knowledge_notes`, `knowledge_links`, `knowledge_sessions`, `knowledge_source_locations`, `knowledge_summaries`의 쓰기 함수는 M02가 소유한다(C1·§8.4). 원바이트는 내용 확인값(SHA256)으로 중복을 막는다. 명시적으로 원파일을 요청할 때만 `runtime/01.원본내보내기/`에 내보낸다. 가격·작도·계획은 각 담당 모듈의 저장본을 읽는다.

### 4. 다른 모듈과의 연결

- **C1·C2(§8.4):** 지식 저장 함수는 M02, 가격 저장·읽기 함수는 M03이 맡는다. M03이 기존 가격 결과 모양을 보존해 제공하면 M02는 조 2b에서 연결한다.
- **C3(§8.1·8.4):** 작도 해석은 M06이 만들고 M09가 조 4에서 세션 맥락에 붙인다. M02가 작도 해석이나 자동 L1 참고선을 만들지 않는다.
- **C6·C7:** 세션 도구 이름·인자는 M09, 대시보드 입구는 M10만 바꾼다.
- **C8(§8.2):** 검사는 M00 실행기로 임시 자료에만 한다. 실제 자료·인증·외부 통신은 사용하지 않는다.

M11은 조사 전에 저장 지식을 읽는다. 지식에 “관심 있다”라고 적는 일은 감시 등록이나 계획 채택과 별개다.

### 5. 이번 개편에서 바뀌는 것 / 그대로인 것 / 없어지는 것

- **바뀜(확정):** 검색 담당 코드를 저장 담당 코드와 나누어 나중에 검색 방식을 교체할 수 있게 한다.
- **유지(확정):** 키워드 검색 결과·페이지 방식, 원문·발언·요약 구분, 근거 ID, 이전 요약, 수정 전 발언. Q3의 가설 검증일·반증 조건·검증 전 비중은 M05 계획 기록에 둔다.
- **없어짐:** M02에서 없앨 지식은 없다. 종료된 매매 사이클 연결 제거는 선행 M01의 결과를 받는다. [의미 검색](../용어집.md), 새 벡터 DB·모델, 뉴스 수집은 이번 범위 밖이다.

### 6. 쓰는 법

세션에서 자료를 주거나 종목·주제의 이전 논의를 불러 달라고 한다. 긴 결과는 다음 페이지와 원문 ID로 이어 읽는다. 요약이 바뀌어도 예전 요약 번호로 당시 생각을 볼 수 있다. 대시보드는 이 모듈을 쓰기 위한 필수 실행 프로그램이 아니며, 새 지식 화면은 만들지 않는다.

### 7. 사용자가 직접 확인하는 방법

5단계의 격리된 검수 자료로 ① 같은 문서를 두 번 저장하고 원문 ID·내용이 보존되는지, ② 사용자 발언과 AI 해석이 구별되는지, ③ 질문을 해결한 뒤 새 세션에서 원래 질문과 해결 기록을 모두 읽을 수 있는지, ④ 이전 요약을 번호로 열었을 때 당시 글이 그대로인지 확인한다. 검색 결과가 없을 때는 “저장된 자료가 없음”으로 표시되고 새 조사나 감시 등록이 시작되지 않아야 한다.

## 작업 지시서

### 1. 범위와 목표

**확정:** M00(조 0)·M01(조 1) 이후 조 2에서 구현한다. 현재 저장 형식과 외부 서비스 호출 서명을 유지하며 검색 경계를 분리한다. M03 병합 뒤 조 2b에서 저장 가격 맥락을 M03 읽기 함수로 연결한다. DB 이관, 요약 재생성, 기존 ID·해시 변경은 없다. Q1~Q3·뉴스 보류·기능 종료 결정을 변경하지 않는다.

**권장 내부 계약:** 새 `knowledge/search.py`에 `KeywordSearch.search_rows(connection, *, query, subjects)`를 둔다. 입력 connection은 `KnowledgeStore._read()`가 연 읽기 전용 연결이며, 반환은 `(item_type, sqlite3.Row)` 목록이다. `item_type`은 `source|note`, 행은 기존 `id,payload,created_at`이다. `query`는 검증을 마친 원문 문자열이며 SQL용 이스케이프는 `KeywordSearch` 안에서 정확히 한 번만 한다. 검색기는 연결을 열거나 닫거나 저장하지 않는다. 입력 검증·`_item` 포맷·정렬·페이지 자르기는 기존 `KnowledgeStore.search`가 소유한다. `KnowledgeStore(path, *, search_backend=None)`의 선택 인자로 대체 검색기를 주입하고 기본값은 `KeywordSearch`로 한다. MCP 인자는 늘리지 않는다.

기존 검색 의미를 그대로 유지한다: query 최대 500자, `%`·`_`·`\`는 문자 검색, 종목/주제는 정확한 교집합, 제목·본문·주제 검색, `(created_at,id)` 내림차순, `offset>=0`, `1<=limit<=200`, 반환 `items,total,offset,next_offset`. 원문·발언 미리보기는 4,000자, 전문 조회는 별도 페이지다. `context`의 해결/대체 판정은 전체 원기록을 대상으로 유지하며 검색 결과의 첫 페이지만 보고 미정 상태를 계산하지 않는다.

### 4. 단계별 구현 순서

1. M00 실행기와 M01 통합 결과를 먼저 받는다. `session_context.py:27`의 `_cycles`, `:103`의 사이클 소비와 `test_session_context.py`는 M01 인계 결과를 기준으로 한다. 현재 줄 번호를 복사해 사이클 기능을 다시 넣지 않는다.
2. 기존 `search`의 검증·필터·정렬·페이지·미리보기 기대값을 합성 입력으로 고정하고 SQL 선택 부분만 `KeywordSearch`로 옮긴다. 선택 인자 없는 기존 생성자의 결과가 같아야 한다.
3. 가짜 검색기를 주입해 저장 구현과 검색기가 분리됐음을 확인한다. `context`의 미정 질문·다음 행동 계산과 요약 저장은 옮기지 않는다. 검색 예외를 빈 결과 성공으로 숨기지 않는다.
4. 조 2b에서 M03 병합 결과의 `saved_price_context(stock_key, *, root)`로 가격 맥락을 교체한다(§8.4). 기존 `prices[].metadata`·`last_completed_saved_bar(day,close,revision)`와 `errors`를 보존하고 복수 series를 하나로 축소하지 않는다. C3 작도 해석은 M06 조 3 → M09 조 4 인계로 확정됐으므로 M02 완료 항목에 넣지 않는다.
5. `tests/suites/M02.txt`에 K02-01~07과 기존 지식·저장 맥락 검사를 등록한다. MCP 합성 자식은 같은 가드를 상속하게 고친다. §6 명령으로 검사하고 서비스 서명·결과 예·C3 인계 경계를 M09와 검토자에게 넘긴다. M03 인계 전에는 조 2b와 K02-07을 미완료로 남긴다.

### 6. 검사 명령

§8.2의 M00 실행기 계약을 쓴다. M00이 고정한 개발 Python으로 WB에서 실행하며, `tests/run_isolated.py`가 제공된 뒤에만 수행한다. 현재 문서 개정에서는 실행하지 않는다.

```powershell
.\.venv\Scripts\python.exe tests/run_isolated.py --module M02
.\.venv\Scripts\python.exe tests/run_isolated.py --module M02 --node test_knowledge_search_contract.KnowledgeSearchContractTests.test_context_uses_price_service_without_writes
```

두 번째 명령은 조 2b 부분 확인용이며 모듈 전체 통과를 대신하지 않는다. `tests/suites/M02.txt`는 M02 소유이며 다음 필수 노드를 등록한다.
