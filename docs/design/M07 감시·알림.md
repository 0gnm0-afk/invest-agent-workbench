작성·개정: 2026-11-17 · DESIGN-3-20261117 · **§8 반영 초안·사용자 승인 전 / 설계 검토 가능** · 구현 조: **2 → 2b(가격 연결) → 조 3 뒤(작도 연결)**

입력: [3단계 설계](<../3단계 설계.md>) **§8 우선**, §2~4·§6~7, [DESIGN-3](../../DECISIONS.md#design-3-20261117)·[SELECT-2](../../DECISIONS.md#select-2-20261117), [기능 목록](<../2단계 기능 목록 초안.md>), [기술부채 진단](<../2단계 기술부채 진단.md>), [ver3.1](../투자에이전트ver3.1.md), [용어집](../용어집.md). 확정 결정은 본문에 반영했고, 남은 계약 공백은 M07-Q07에 적었다. 이번 개정은 문서만 수정했으며 시험·운영 실행은 하지 않았다.

## 앞 절반 — 설명서

### 1. 하는 일

명시 등록한 종목의 기술 신호·계획·차트 선을 살피고, 보유 종목의 가격 위험은 자동으로 살핀다.
저장된 마지막 계좌 관측과 완료된 하루 가격을 쓰며, 자료의 기준 시각과 보류 이유를 보여 준다.
알림 판정과 Telegram 전송 결과를 따로 기록하고, 주문이나 가설 자동 판정은 하지 않는다.

### 2. 입력과 출력

| 입력 | 출력 |
|---|---|
| 명시 등록한 종목·규칙, 저장 일봉·거래일 | 신호 발생·신호 없음·자료 부족으로 보류, 판정일·가격 근거 |
| 채택 계획·작도 수정 번호, 마지막 저장 보유 내역 | 선 접근·돌파·이탈, 보유 종목의 가격 경고, 기준 시각·과거 이력 |
| 전송 가능한 사건과 기존 승인 수신처 | 성공·실패·결과 불명 및 중복 전송 방지 기록 |

기술 신호는 매매 시점을 점검하는 도구다. 오래된 가격이나 불완전한 보유 내역은 정상으로 꾸미지 않는다. 자동 L1 추세선은 참고선이므로 감시·알림에 쓰지 않는다.

### 3. 저장 위치

워크벤치의 기존 DB를 그대로 쓴다. 아래 테이블의 쓰기 함수와 전송 원장은 M07이 관리한다(§8.4 C1).

| 저장소 | 관리 내용 |
|---|---|
| `runtime/records.sqlite3` | `technical_watches`, `technical_states`, `technical_events`: 기술 신호 등록·상태·사건 |
| `runtime/chart-workspaces.sqlite3` | `scenario_monitors`, `scenario_monitor_history`, `scenario_monitor_events`, `scenario_monitor_evaluations`: 계획·작도 감시와 이력 |
| `runtime/trailing-warnings.sqlite3` | `monitors`, `warnings`: 고점과 이동평균 경고 |
| `runtime/telegram-delivery/delivery.sqlite3`, 같은 폴더 `latest.json` | `deliveries`: 전송 원장과 최근 상태 |

기존 사건·전송 기록·과거 작도와 계획은 지우지 않고, 별도 이관 DB도 만들지 않는다.

### 4. 다른 모듈과의 연결

- **C1·C2:** M03의 저장 가격 읽기 함수를 쓴다. 각 모듈이 자기 쓰기 함수를 관리하고, 다른 모듈은 그 함수를 부른다.
- **C3·C5:** M05의 채택 계획, M06의 읽기 전용 작도, M08의 마지막 저장 보유 관측을 받는다. 기술 신호·시나리오는 명시 등록하고, 트레일링은 보유 종목을 자동으로 살핀다.
- **C6·C7:** 세션 도구는 M09, 화면 연결은 M10, 실행과 전송 시점은 M12가 맡는다. 계좌를 새로 조회하지 않아도 전송할 수 있게 분리한다.
- **C8:** 구현 검사는 M00 격리 실행기로 합성 자료만 사용한다. 실제 자료와 화면 확인은 별도 운영 적용이다.

### 5. 이번 개편에서 바뀌는 것 / 그대로인 것 / 없어지는 것

- **바뀌는 것:** 가격·작도 읽기를 담당 모듈의 함수로 모으고, 계좌 자동 조회와 전송의 연결을 끊는다. 계좌는 마지막 저장 시각을 표시한다.
- **그대로인 것:** 기존 CCI·RSI·MACD 조건, 고점의 95% 기준선과 5일·10일 이동평균 경고, 회복 뒤 재진입 알림, 과거 이력·중복 방지다. 오래된 계좌·가격의 보류 규칙도 유지한다.
- **없어지는 것:** M01이 제거하는 매매 사이클·옛 위험 알림은 되살리지 않는다. 뉴스는 보류한다. 가설 검증일·반증 조건·검증 전 비중은 읽을 수만 있으며 자동 판정하지 않는다.

### 6. 쓰는 법

- **세션:** `investment_signal_rules/status/watch`로 조건·저장 상태·등록을 다룬다. 대화에서 언급하거나 보유했다고 기술 신호를 자동 등록하지 않는다. 보유 가격 경고는 저장 관측을 바탕으로 자동 감시한다.
- **대시보드:** M10의 시나리오 감시·가격 위험 화면에서 계획·선·판정일·계좌 기준 시각·보류 이유를 확인한다. 계좌 화면은 없앤다. 실제 알림·06:40 예약은 6단계까지 중지 상태다.

### 7. 사용자가 직접 확인하는 방법

5단계의 합성 종목·격리 저장소에서 미등록 보유 종목은 가격 위험만, 명시 등록 종목은 등록한 신호·시나리오만 평가되는지 본다. 선을 고치거나 삭제하면 이전 이력이 남고, 오래된 자료는 보류되어야 한다. 모의 수신함은 같은 사건을 한 번만 받고 전송 불명 사건은 다시 받지 않아야 한다. 실제 Telegram은 쓰지 않는다.

## 뒤 절반 — 작업 지시서

### 1. 범위와 목표

**확정 범위:** `signals/`, `scenarios/`, `alerts/`의 기술 신호·시나리오·가격 경고·전송 서비스를 유지하며 §8.1·8.4·8.6의 경계를 적용한다. M00(조 0)와 M01(조 1) 병합 뒤 조 2를 시작한다. M03 병합 뒤 **M07이 조 2b 가격 소비 변경**, M06 조 3 결과 뒤 **M07이 작도 소비 변경**을 한다. M07-Q07 결정 전에는 작도의 실제 C3 전환을 완료로 처리하지 않는다. 줄 번호는 2026-11-17 코드 기준이며 M01 병합 뒤 같은 함수로 다시 찾는다.

신호 식은 `CCI20 −100 상향교차 AND SMA20[t] < SMA20[t−5]`, CCI 단독, RSI14 30 상향교차를 따로 유지한다. 하락 결합은 `MACD(12,26,9) 당일 신규 하향교차 AND 당일 포함 최근 3거래일 RSI14 60 신규 하향교차`다. CCI+RSI 새 결합은 추가하지 않는다. 가격 경고는 `H×0.95`, 각 선의 `종가 <= 기준선 + 0.5×ATR14`, 첫 진입·회복 후 재진입 및 기존 사건 ID를 유지한다.

**C3 소비 계약(§8.4):** M06의 읽기 전용 함수에서 최신 저장 작도와 채택 계획이 참조한 정확한 revision을 구별한다. 미채택 AI 제안과 §8.1의 자동 L1 추세선은 감시 입력에서 제외한다. 비교 가격은 저장된 최신 완료 일봉 종가와 날짜이며, 거리 = 종가 − 선값, % = 거리 / 선값 × 100이다. 시간틀은 작도의 저장값, 없으면 일봉이다. 수정 시각은 `workspace_saved_at`을 쓰고 도형별 시각을 만들지 않는다. 중간 revision 보존·등록 시 일관된 읽기 계약은 Q07 결정이 필요하다.

**범위 제외:** 운영 활성화, 실제 계좌·시세 조회, 인증·수신처 변경, 주문·환전, 뉴스, 종료 기능, 실적일 수집과 가설 자동 판정. `launch/daily.py`·`scheduled.py`의 계좌 조회/전송 분리 구현은 M12(조 5), 앱 NH 직접 조회 제거는 M08, 도구·HTTP 연결은 M09·M10이다.

### 3. 건드리면 안 되는 것

### 4. 단계별 구현 순서

1. **조 2 선행 확인:** M00 실행기·가드와 M01 병합 결과를 확인한다. 사이클 호출 제거·`atomic_io.py` 인계를 정적으로 확인하고 미완료는 M01에 돌려준다. M07 시험 선택 목록을 만든다.
2. **조 2 규칙 보존:** 합성 입력으로 기존 신호·보유 자동 트레일링·명시 시나리오·이력·전송 상태를 고정한다. 기술 신호에 계획/작도 의무 등록을 추가하지 않는다. 저장 계좌 기준 시각과 기존 신선도·완전성 보류를 유지한다.
3. **조 2b 가격 연결:** M03 병합 뒤 `signals/store.py`·`alerts`를 공통 읽기로 교체한다. 완료일·가격 정정·구 내장 bars·`bars_ref`에서 결과와 참조/해시가 같은지 격리 시험한다. API가 부족하면 M03에 돌려주고 직접 SQL이나 가격 쓰기로 우회하지 않는다.
4. **조 3 뒤 작도 연결:** 조 2에서는 계약 합성 구현으로 경계를 준비한다. M06 제공 및 Q07 결정 뒤 M07이 C3 읽기로 전환하고 미채택 제안·자동 L1 입력을 배제한다. 중간 revision·삭제/복원·동시 수정과 과거 판정 보존을 검증한다. Q07 미해결 상태는 후속 연결 미완료로 남긴다.
5. **전송·인계:** M07 소유 원장의 중복 방지와 성공/실패/불명을 가짜 sender로 검증한다. 새 계좌 조회가 없어도 기술 신호 전송 서비스를 호출할 수 있음을 확인한다. M12에는 저장 관측 실패·시각·보류를 전달하는 서비스와 계좌 조회/전송 분리 조건을 넘긴다. M12가 조 5에서 실행기 결합을 끊으며 M07이 `launch/`를 수정하지 않는다.
6. **완료 판정:** §6의 모듈 전체 검사를 실행하고 JSON 영수증을 확인한다. 조 2·2b 결과와 조 3 뒤 후속 연결 결과를 구분하며, 필수 후속 검사와 Q07이 남으면 전체 구현 완료로 표시하지 않는다.

### 6. 검사 명령

§8.2의 **M00 실행기 계약**을 따른다. 아래는 M00 구현·병합 뒤 워크벤치에서 실행할 명령이며, 지금 파일이 이미 구현되었거나 검사를 실행했다는 뜻이 아니다.

```powershell
.\.venv\Scripts\python.exe tests/run_isolated.py --module M07
```

필요한 노드만 확인할 때도 `tests/run_isolated.py --module M07 --node 노드ID` 형식을 쓰며 전체 모듈 검사를 대신하지 않는다. M07 소유 `tests/suites/M07.txt`에 다음 선택 목록을 등록한다.

```text
test_technical_signals.Indicators
test_technical_signals.Persistence
test_scenario_monitor.Scenarios
test_scenario_flow.ScenarioFlowTests
test_trailing_warnings.Warnings
test_trailing_warnings.SelectedSeries
test_trailing_warnings.SavedAlertInputs
test_telegram_warnings.TelegramWarnings
test_monitor_contracts
```

외부 네트워크(DNS·외부 connect), 운영 runtime·DB, 인증 파일, Windows 사용자 환경변수는 접근 0이다. OS 임시 workspace의 합성 파일·DB, loopback(`127.0.0.1`)·socketpair, 같은 가드를 상속한 임시 fixture 자식 프로세스만 허용한다. 영수증 JSON은 OS 임시 폴더에 남긴다. 위 DPAPI 시험은 합성 보호 함수로 바꾸고, `verify_scenario_saved.py` 같은 실제 자료 재생 도구와 운영 대시보드를 선택 목록에 넣지 않는다. 직접 `unittest discover`로 우회하지 않는다.

### 운영 적용(Claude, 사용자 승인)

실제 감시·전송 DB 대조, 기존 기록 보존 확인과 실제 대시보드 확인은 구현 완료 뒤 별도 단계다. Claude가 사용자 승인 후 대상 파일·DB의 전후 해시와 관측 시각을 기록한다. 실제 runtime·DB를 읽거나 변경하는 작업은 이 단계에서만 다룬다. 실제 계좌·시장 조회, Telegram 발송, 예약 재개는 이 문서 개정이나 구현 완료로 승인되지 않으며 6단계의 별도 승인 범위로 남긴다.

### 7. 브랜치·커밋 방법

향후 구현 승인을 받은 뒤 기존 변경을 확인하고 M00·M01 병합 기준의 `module/M07-감시알림` 브랜치를 사용한다. 소유 파일·M07 시험·`tests/suites/M07.txt`만 명시 경로로 스테이징하고 cached diff를 읽는다. 조 2b와 조 3 뒤 후속 연결도 M07 담당이 별도로 검수받는다. 운영 DB·runtime·인증·다른 모듈 변경은 포함하지 않으며 워크벤치 코드 이력과 공통 Git 문서 이력을 구분한다. **이번 개정에서는 사용자 지시로 브랜치 변경·스테이징·커밋을 하지 않는다.**
