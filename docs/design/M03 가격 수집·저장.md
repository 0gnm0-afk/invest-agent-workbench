# M03 가격 수집·저장

개정: 2026-11-17 · DESIGN-3-20261117 · **초안·§8 반영, 사용자 승인 전** · 구현 조 **2 → 소비자 연결 조 2b**

입력: [3단계 설계](<../3단계 설계.md>) 전체, 특히 **§8을 이전 계약·순서보다 우선**한다. [DESIGN-3](../../DECISIONS.md#design-3-20261117)·[SELECT-2](../../DECISIONS.md#select-2-20261117), [기능 목록](<../2단계 기능 목록 초안.md>) MOD-02, [기술부채](<../2단계 기술부채 진단.md>) DEBT-02·03B·04, [ver3.1](../투자에이전트ver3.1.md) §4도 따른다.

판정: **설계 검토 가능**. 기존 질문 5개는 결정에 반영했다. 루트 Toss 보존 파일의 종료 여부와 C9 영수증의 기존 결과 매핑을 새 질문으로 남긴다. 이번 개정은 문서와 소스를 정적으로 대조했으며 코드 변경·시험·수집·앱 실행을 하지 않았다.

## 앞 절반 — 설명서

### 1. 하는 일

승인된 전체 종목의 하루 가격과 거래량을 Toss에서 받아 차트·분석·감시가 함께 쓰게 한다.
가격을 나중에 고쳐 받아도 과거 분석이 보았던 값은 다시 읽을 수 있게 남긴다.
받지 못한 자료와 잘못된 자료를 구분해 보여 준다.

### 2. 입력과 출력

| 입력 | 출력 |
|---|---|
| 승인된 종목 범위·제외 목록·시장별 완료 거래일 | 종목별 하루 가격과 거래량, 출처·기준일 |
| 저장 가격과 직전 수집 기록 | 빠진 날짜와 직전 하루의 대조 결과, 과거 가격 버전 참조 |
| 수집·품질 확인 결과 | 실패·부분 이력·결측 이유와 수집 완료 영수증 |

가격을 수집했다고 감시를 등록하지 않는다. 보유 종목의 가격 위험 경고와 명시 등록 종목의 기술 신호·시나리오 감시는 M07이 맡는다.

### 3. 저장 위치

가격은 기존 `runtime/ohlcv.sqlite3`, 원 응답과 수집 기록은 `runtime/records.sqlite3`의 `record_*` 표에 보존한다. M03이 공용 저장 함수를 관리하고, M04 재무도 이 함수를 이용한다. 과거 원문·해시·가격 버전은 바꾸지 않는다.

### 4. 다른 모듈과의 연결

- **C1·§8.4:** 가격과 공용 원문 저장 함수는 M03 소유다. 다른 모듈은 그 함수를 불러 쓴다.
- **C2·§8.4:** 저장 가격 읽기 함수를 먼저 만들고 M02·M05·M07이 M03 병합 뒤 조 2b에서 연결한다. M06은 차트 이력을 읽는 함수만 사용한다.
- **C6·C7:** 세션 도구와 화면 연결은 M09·M10이 맡는다.
- **C8·§8.2:** 합성 자료로 격리 검사한다. 실제 자료·대시보드 확인은 별도 운영 적용이다.
- **C9·§8.3:** M03의 수집 완료 영수증으로 M12가 실행 성공 여부를 판단한다.

### 5. 이번 개편에서 바뀌는 것 / 그대로인 것 / 없어지는 것

| 구분 | 내용 |
|---|---|
| 바뀌는 것 | Toss 단일 수집에 맞춰 코드·설명을 정리하고 공용 가격 읽기와 완료 영수증을 제공한다. |
| 그대로인 것 | 전 종목 수집 범위·제외 정책, 누락 날짜와 직전 하루 대조, 가격 정정 이력과 과거 입력 재현 |
| 없어지는 것 | 새 가격을 NH로 보완하는 경로. 과거 NH 저장 자료를 읽는 기능은 남긴다. |

EPS 추정치 수집, 새 종목 선별, 자동 주문, 뉴스 개편은 포함하지 않는다.

### 6. 쓰는 법

- **세션:** 저장 가격·완료 거래일·출처를 요청한다. 저장 조회가 새 수집을 일으키지 않는다.
- **대시보드:** 종목을 검색해 차트와 기준일을 확인한다. 실제 수집 재개는 별도 운영 승인 뒤에 한다.

### 7. 사용자가 직접 확인하는 방법

5단계에서 합성 자료로 확인한다. 실제 DB·대시보드를 쓰는 확인은 별도 운영 적용이다.

1. 관심 목록 밖의 종목도 차트를 볼 수 있고 감시는 새로 등록되지 않는다.
2. 가격을 정정해도 과거 분석은 당시 가격을 그대로 보여 준다.
3. 수집 실패·시총 결측·부분 이력이 정상이나 0으로 바뀌지 않는다.
4. 새 수집은 Toss, 과거 NH 자료는 당시 출처로 표시된다.

## 뒤 절반 — 작업 지시서

### 1. 범위와 목표

**확정:** M00 격리 실행기와 M01 종료 기능 제거·유지 helper 이동을 합친 뒤 조 2에서 구현한다. 설명서 승인 전에는 구현하지 않는다. 이번 문서 개정에서는 코드·시험·브랜치 작업을 실행하지 않는다.

M03은 Toss 신규 수집과 저장 근거 재현을 분리하고, 기존 가격·고정 참조·품질 계약을 보존하며, C2 읽기 함수와 C9 영수증을 제공한다. 전 종목 수집 범위를 관심 종목으로 줄이거나 감시 범위를 넓히지 않는다. DB 구조 변경·자료 이관은 기본 범위가 아니다.

**확정 계약(§8.3·§8.4):**

- C1의 단독 소유는 **쓰기 함수의 소유**다. `record_*` 공용 저장 API(`records/store.py` 등)와 `market/financial_price_receipts.py`는 M03 소유이고 M04는 이를 호출한다. 기존 `pack_price_input`의 가격 변형 보존도 유지하며 순수 읽기 함수로 축소하지 않는다.
- `market/daily.py`는 조 2부터 M03 소유다. `launch/daily.py`는 M12 소유다.
- `market/history/chart.py`의 수집·쓰기·읽기는 M03 소유다. M06에는 저장 읽기 함수만 제공한다.
- C2는 `saved_price_context(stock_key, *, root)`와 직접 SQL을 대체할 bars 읽기를 제공한다. 전자는 기존 `[{metadata, last_completed_saved_bar: {day, close, revision} 또는 null}]` 응답을 보존한다. M02 `session_context`, M05 `direct.py`, M07 `signals/store.py`·`alerts`는 M03 병합 뒤 각자 조 2b에서 변경한다.
- C9는 `{target_trade_date, completed, failed, status, provenance, sha256}`를 M12에 제공한다. 현재 시장 run의 수집 결과·기준일·출처·해시를 근거로 만들고 종료된 `priority-review.json`을 사용하지 않는다. 다만 현재 run에는 이 여섯 필드가 그대로 있지 않다(Q7). 필드별 매핑과 해시 대상을 확정한 뒤 M01의 최소 대체 결과를 이어받아 M12에 인계한다.

기존 `PriceStore(path)`, `find(stock)`, `observation(series_id, kind=None)`, `read(reference)`, `daily_seed(stock, cutoff, revision=None)`의 입력·응답과 오류 의미를 보존한다. `read`는 날짜순 일봉을 반환하고 동일성·행 수·해시 불일치를 거부한다. DB 부재·빈 이력·실패·동일성 모호함을 같은 정상 상태로 합치지 않는다. M07의 구 snapshot 내장 bars도 원문 해시·고정 참조를 검증하는 M03 읽기 경계로 받으며 재이관하거나 새로 쓰지 않는다.

**권장:** Toss 클라이언트는 명시된 신규 수집 경로에서만 만들고, 저장 조회·과거 NH 재생은 인증이나 외부 요청 없이 끝낸다. 시험용 root·DB 경로·시각·공급자 응답 주입을 끝까지 유지한다.

### 4. 단계별 구현 순서

1. **선행 확인:** 설명서 승인, M00 실행기, M01 병합과 helper 이동 결과를 확인한다. §8.3·§8.4의 파일 소유권을 적용하고 기존 변경을 보존한다.
2. **신규/재현 경로 정리:** 신규·실패·recover·재시도에서 새 NH 요청을 제거한다. 저장 NH 재생은 원문·해시·동일성을 검증하고 누락 시 실패한다. 보고서·도움말도 같은 출처 구분을 쓴다. Q7 해결 뒤 C9 영수증을 만들고 M12에 계약을 인계한다.
3. **저장·읽기 경계:** 공용 원문·재무 가격 API를 보존하고 C2 함수와 차트 저장 읽기를 제공한다. 기존 응답과 구 snapshot 호환 fixture를 함께 넘긴다. M03 병합 뒤 M02·M05·M07은 각자 조 2b, M06은 조 3에서 연결한다.
4. **격리 검사·인계:** `tests/suites/M03.txt`에 §5의 노드를 등록하고 M00 실행기로만 검사한다. M01·M08 제거 후 루트 helper 참조를 다시 정적으로 확인해 Q6의 종료 판단 근거를 넘긴다. 실제 수집·DB 대조·대시보드 실행은 완료 조건에 넣지 않는다.

### 6. 검사 명령 (M00 실행기 기준)

§8.2의 확정 형식이다. M00 구현·병합 후 워크벤치에서 실행하며, **이번 문서 개정에서는 실행하지 않는다.**

```powershell
.\.venv\Scripts\python.exe tests/run_isolated.py --module M03
```

M03이 관리할 `tests/suites/M03.txt` 선택 목록:

```text
test_market_single_provider
test_price_read_contract
test_prices.PricesTests
test_incremental_market.IncrementalMarketTests
test_record_prices.RecordPriceTests
```

특정 실패만 다시 볼 때도 `tests/run_isolated.py --module M03 --node 노드ID` 형식을 쓴다. 목록의 시험 import와 합성 경로 격리는 M00이 제공하며, M03은 목록의 노드와 §5 완료 기준을 함께 유지한다. 결과 영수증 JSON은 OS 임시 폴더에 남긴다.

C8은 외부 DNS/connect·운영 runtime/DB·인증 파일·Windows 사용자 환경변수 접근을 금지한다. 임시 합성 파일·DB, loopback(`127.0.0.1`)·socketpair, 같은 가드를 상속한 임시 fixture 자식 프로세스만 허용한다. `daily.ps1`, 실수집 CLI, MCP 서버, 예약, 실제 대시보드는 검사 명령으로 사용하지 않는다. `--offline`도 DB 무변경 보장이 아니다.

### 운영 적용(Claude, 사용자 승인)

구현 완료와 별개다. 필요하면 Claude가 사용자 승인 뒤 실제 저장 가격·고정 참조·원문 해시·대시보드 표시를 대조하고 전후 해시와 결과를 남긴다. 실제 runtime 보관·삭제는 M01/M13 범위로 넘긴다. 수집 재개·계좌·Telegram·예약은 이 모듈 구현 승인에 포함되지 않으며 기존 운영 동결을 유지한다.
