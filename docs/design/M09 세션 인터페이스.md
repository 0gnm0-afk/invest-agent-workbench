# M09 세션 인터페이스

작성·개정: 2026-11-17 · 상태: **§8 반영 초안·설명서 승인 전** · 상세 설계 · 설계 가능 / 설계 검토 가능

입력: [3단계 설계](<../3단계 설계.md>) 전체, **특히 §8(앞선 계약·순서보다 우선)**, [ver3.1](../투자에이전트ver3.1.md), [용어집](../용어집.md). `확정`은 상위 결정, `권장`은 구현안이다. 이번에는 문서와 소스만 읽고 문서만 개정했다. 아래 검사는 향후 구현용이며 실행하지 않았다.

## 설명서

### 1. 하는 일

세션에서 지식·분석·논의·계획을 읽고 저장하는 도구의 입구를 정리한다.
직접 그린 선과 자동 L1 참고선을 글로 읽는 `investment_drawings`를 추가한다.
종료한 매매 사이클 도구 다섯 개는 없애고, 뉴스 도구 세 개는 보류 상태로 둔다.

### 2. 입력과 출력

정확한 종목 키, 분석·계획의 ID와 수정 번호를 받는다. 작도 읽기는 최신 저장 작도와 채택 계획이 사용한 당시 작도를 구분하고, 저장된 최신 완료 일봉 종가·날짜와 선까지의 거리를 보여 준다. 자동 L1 추세선은 계산한 화면 구간과 함께 별도로 보여 준다.

구간을 지정하지 않으면 대시보드 기본 구간을 쓴다. 새 가격 조회·작도 저장·계획 채택은 하지 않는다. 기존 `analysis_read`는 고정 입력(snapshot)을 저장할 수 있으므로 이 도구와 구별한다.

### 3. 저장 위치

M09가 직접 쓰는 DB 테이블은 없다. 지식은 M02, 분석·계획은 M05, 작도는 M06의 저장 함수를 이용한다. 도구 정의는 워크벤치 `scripts/session_mcp.py`와 `scripts/analysis/mcp.py`에 둔다.

### 4. 다른 모듈과의 연결

- **C1·§8.4:** 저장 책임은 각 모듈에 있고 M09는 그 함수를 호출한다. 과거 사이클 테이블과 데이터는 보존한다.
- **C3·§8.1·§8.4:** M06의 작도 읽기를 새 도구와 `investment_context`에 연결한다. 자동 L1 선은 사용자 작도와 구별하며 감시·알림에 쓰지 않는다.
- **C6·C7·§8.3:** 조 1에서 M01이 종료 도구만 먼저 제거한다. 조 2부터 MCP 이름·인자는 M09, HTTP·화면 셸은 M10이 맡는다.
- **C8·§8.2:** M00 실행기로 합성 자료를 검사한다. 실제 자료·인증·외부 네트워크에는 접근하지 않는다.

M05→M06 결과를 받은 조 4에서 M10과 병렬로 구현한다. M11의 `eps-research`가 이 도구들을 사용한다.

### 5. 이번 개편에서 바뀌는 것 / 그대로인 것 / 없어지는 것

- **바뀜:** 작도 읽기와 맥락 연결, 계획의 가설 검증일·반증 조건·검증 전 비중 안내, `eps-research`→`deep-research` 조사 안내.
- **그대로:** 기존 지식·분석·논의·계획의 ID·페이지 읽기·권한, 명시적 기술 신호 등록, 뉴스 세 도구의 코드·인자.
- **없어짐:** 사이클 다섯 도구의 노출과 Codex 실행 URI 안내. 세션으로 넘길 때는 문맥 복사만 제공한다.

### 6. 쓰는 법

“이 종목에 그린 선을 읽어줘”라고 요청한다. 필요하면 볼 기간과 일·주·월 시간틀을 함께 말한다. 종목 맥락을 읽을 때도 같은 작도 설명을 받는다. 계획 저장은 초안 작성이며 사용자 채택은 별도다.

### 7. 사용자가 직접 확인하는 방법

5단계 합성 자료에서 ① 대시보드 없이 지식·논의·작도를 읽는다. ② 최신 작도와 채택 당시 작도가 구분되고 자동선의 계산 구간이 보이는지 확인한다. ③ 계획 세 칸의 원문과 채택 상태가 유지되는지 본다. ④ 종료 도구 다섯 개가 없고 뉴스 도구 세 개는 목록에 남는지 본다. 실제 자료 확인은 뒤의 운영 적용으로 분리한다.

## 작업 지시서

### 1. 범위와 목표

**확정:** 조 4, 선행 M00·M01·조 2 서비스·M05→M06. 도구 등록·인자·설명·서비스 전달만 담당한다. 업무 로직·SQL·가격 수집·계좌 조회를 추가하지 않는다.

**C3 확정 계약(§8.1·§8.4):** 도구 이름은 `investment_drawings`. (a) 공유 작업공간의 최신 저장 작도, (b) 채택 계획이 참조한 정확한 작도 revision을 구분한다. 채택되지 않은 AI 제안은 제외한다. 비교 가격은 저장된 최신 완료 일봉 종가와 날짜다. 거리 = 종가 − 선값, 거리 % = (종가 − 선값) / 선값 × 100. 작도에 저장된 시간틀을 사용하고 없으면 일봉이다. 수정 시각은 `workspace_saved_at`이며 도형별 수정 시각을 만들지 않는다. 값·결측·무효 사유는 M06 결과를 그대로 전달한다.

자동 L1 추세선은 위 두 묶음과 별도의 묶음으로 구간 시작·끝, 방향, 직선 좌표, 계산에 쓴 화면 구간(시작·끝·시간틀)을 전달한다. 저장·채택·감시에 연결하지 않는다. **권장 인자:** `investment_drawings(stock_key, start=None, end=None, timeframe=None)`. 구간 생략 시 M06의 대시보드 기본 구간 규칙을 쓰며 M09에서 별도 기간을 정하지 않는다. M06이 제공하는 구간 검증·상태를 전달하고 DB 경로·수집·채택 권한은 도구 인자로 노출하지 않는다.

`investment_context`의 기존 인자·페이지·지식 결과를 유지하면서 `stock_key`가 있을 때 같은 C3 서비스를 조합한다. **권장 반환 필드:** `operations.drawing_context`. 기존 `operations.drawings` 원본은 호환성을 위해 유지하고 새 필드가 C3 설명임을 안내한다. 주제만 조회할 때 종목이나 구간을 추측해 작도를 읽지 않는다. 종목별 구간 지정은 독립 `investment_drawings`를 사용한다.

현 코드 34개에서 M01이 사이클 5개를 제거하고 M09가 1개를 추가하므로 **목표는 30개**다. 개수뿐 아니라 아래 이름 집합을 검사한다.

### 4. 단계별 구현 순서

1. **인계 확인:** M00 실행기, M01의 사이클 5개 제거본, M02·M05·M06·M07 계약을 받는다. M06의 L1 미결이 있으면 관련 자동선 연결만 보류하고 임의 산식을 만들지 않는다.
2. **등록·맥락 연결:** 목표 30개 집합을 고정한다. `investment_drawings`를 등록하고 `investment_context`에 동일 서비스를 붙인다. 쓰기 가능한 capture/shared 경유나 별도 계산은 금지한다.
3. **설명 맞추기:** Q3 원문 저장, 초안/채택 구분, M11 조사 순서, 문맥 복사 안내를 반영한다. 뉴스 함수는 변경·호출하지 않는다.
4. **격리 검사:** M09 선택 목록을 작성하고 아래 실행기로만 검사한다. C3 임시 DB·파일 무변경과 stdio 자식 guard 상속까지 확인한다. M10·M11에 이름·인자·결과 예시를 인계한다.

### 6. 검사 명령

§8.2 확정 규약이다. 구현 승인 후 WB에서 M00이 마련한 독립 Python으로 실행한다. **이번 개정에서는 실행하지 않는다.**

```powershell
.\.venv\Scripts\python.exe tests/run_isolated.py --module M09
```

선택 목록은 **`tests/suites/M09.txt`**다. 신규 계약 노드, 기존 `test_analysis_direct.DirectAnalysisTests`의 `test_historical_reads_preserve_ids_without_loading_current_prices`, `test_discussion_and_plan_use_existing_revision_and_never_adopt`, `test_unexposed_authority_and_risk_writes_fail_before_store_access`, `test_session_mcp_direct.DirectSessionMcpTests.test_existing_snapshot_and_record_roundtrip_without_dashboard`를 등록한다. 필요한 개별 노드 재검사는 같은 명령에 `--node 노드ID`를 붙인다.

M00이 import 전 guard, OS 임시 합성 workspace, 동일 guard의 fixture 자식 프로세스를 제공한다. loopback(127.0.0.1)·socketpair는 허용되지만 외부 네트워크·운영 프로세스 연결은 금지다. 결과 JSON은 OS 임시 폴더에 남긴다. SDK stub 검사와 실제 fixture stdio 검사를 구분하며 누락·차단·skip을 통과로 보고하지 않는다. 실행기·선택 목록이 미구현이면 완료 판정을 보류하고 직접 unittest나 운영 MCP 실행으로 대체하지 않는다.

### 7. 브랜치·커밋 방법

향후 승인된 구현은 WB `module/M09-session-interface`에서 M09 파일만 수정한다. M01과 조 2·3 인계를 먼저 반영하고 M10 파일을 편집하지 않는다. 검증 뒤 변경 경로만 stage·cached diff 확인·로컬 커밋한다. 공통 Git에는 이 모듈 문서만 별도로 다룬다. **이번 문서 개정은 브랜치 생성·stage·커밋·STATUS·DECISIONS 갱신을 하지 않는다.**
