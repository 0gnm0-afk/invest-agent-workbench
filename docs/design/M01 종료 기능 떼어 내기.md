# M01 종료 기능 떼어 내기

작성·개정: 2026-11-17 KST · 상태: **§8 반영 초안·사용자 승인 전** · 조 **1·단독** · 준비도: **설계 검토 가능**

입력: [3단계 설계](<../3단계 설계.md>) **§8 우선**, §2~4·6~7, [SELECT-2](../../DECISIONS.md#select-2-20261117), [기능 목록](<../2단계 기능 목록 초안.md>), [기술부채 진단](<../2단계 기술부채 진단.md>). 기존 상세 설계의 모듈 작업 지시서를 개정했다. `확정`은 §8의 결정, `권장`은 구현안, `결정 필요`는 끝의 새 열린 질문이다. 실제 코드와 맞지 않는 자동선·수집 영수증 부분은 M01-Q08·Q09로 남긴다. 이 문서 개정에서는 시험·운영 적용을 하지 않았다.

## 앞 절반 — 설명서

### 1. 하는 일 (세 줄 이내)

종목 선별·섹터 관찰·옛 매매 사이클·옛 위험 계산을 실행 흐름에서 뺀다.
남길 기능의 공통 코드는 먼저 옮기고, 과거 기록은 그대로 둔다.
실제 작업 자료의 보관·삭제는 Claude가 사용자 승인 뒤 따로 한다.

### 2. 입력과 출력

| 입력 | 출력 |
|---|---|
| 종료 목록과 현재 코드의 연결 | 종료 기능을 부르지 않는 코드와 변경 목록 |
| 개발자가 만든 가짜 자료 | 남길 기능과 보관 도구의 검사 결과 |
| 운영 적용 때 승인한 자료 목록 | ZIP 보관본, 파일별 내용 확인값(SHA-256), 처리 영수증 |

### 3. 저장 위치 (C1 소유 테이블·파일)

새 업무 DB는 만들지 않는다. `trade_cycle*` 테이블과 데이터·ID는 그대로 보존하고 쓰기 코드와 조회 도구만 없앤다. 합성 시험 자료는 OS 임시 폴더에 둔다. 실제 보관본은 **권장 경로** `99.아카이브/09.runtime정리/`에 M01 이름으로 남기며, M13과 파일명이 겹치지 않게 한다.

### 4. 다른 모듈과의 연결 (§8 반영 계약)

- **C1:** DB를 쓰는 함수는 소유 모듈이 관리한다. M01은 사이클 테이블을 삭제·변환하지 않는다(§8.4).
- **C2·C5:** 가격 저장소 읽기는 M03의 함수로 연결하고, 보유 자동 가격 경고·미보유 명시 감시의 경계를 유지한다(§8.1·8.4).
- **C6·C7:** 조 1에서만 M01이 공유 화면·MCP 파일의 종료 참조를 지운다. 조 2부터 M09·M10의 단독 소유를 따른다(§8.3).
- **C8:** M00 실행기로 가짜 파일·DB를 검사한다. 실제 자료·인증·외부 네트워크에는 접근하지 않는다(§8.2).
- **C9:** 선별 결과 대신 수집 완료 영수증을 쓴다. M03이 제공하고 M12가 사용한다. 현재 코드의 필드 대응은 Q09로 확인한다(§8.3).

M00 다음에 구현한다. 공통 보관 도구와 미처리 목록은 M13에, 새 L1 자동선은 M06에 넘긴다.

### 5. 이번 개편에서 바뀌는 것 / 그대로인 것 / 없어지는 것

| 구분 | 내용 |
|---|---|
| 바뀜 | 남길 기능의 공통 코드를 옮기고 종료 기능과의 연결을 끊는다. |
| 그대로 | 일봉·종목 검색·차트·사용자 작도·지식·분석·계획·재무·계좌 관측 저장. 기술 신호는 명시 등록, 가격 위험 경고는 보유 종목 자동 감시를 따른다. |
| 없어짐 | 스크리닝·섹터·오늘의 작업대 후보, 36조합 사이클·그 알림, 옛 위험·보호 규칙, 루트 스크립트 33개. 옛 자동 추세선(trendln)도 종료한다(§8.7). |
| 다른 모듈 | 계좌 화면은 M10, 앱 계좌 직접 조회는 M08·M12, 조사 스킬은 M11, 가설 계획 칸은 M05, 새 L1 자동선은 M06. 뉴스는 보류 유지. |

### 6. 쓰는 법 (세션에서·대시보드에서)

세션의 지식·논의·계획과 대시보드의 종목 검색→차트→작도를 이어 쓴다. 옛 사이클을 새 계획으로 자동 변환하지 않는다. 새 화면이나 예약 버튼은 만들지 않는다.

### 7. 사용자가 직접 확인하는 방법 (5단계 검수)

M01 검사 영수증에서 종료 호출이 사라졌는지, 남길 기능과 과거 기록 보존 검사가 통과했는지 확인한다. ZIP 검사는 가짜 파일의 수·크기·내용이 모두 같아야 한다. 실제 자료 정리 결과는 별도의 운영 적용 영수증으로 확인한다.

### 4. 단계별 구현 순서

1. **기준과 미결 경계를 확인한다.** M00 병합과 양쪽 Git 변경을 확인하고 관련 없는 변경을 보존한다. §8의 확정 목록을 적용하되 Q08 자동선 처리와 Q09 영수증 대응은 설계 답을 받은 뒤 고정한다. 현재 실행 중인 프로세스를 임의로 종료하지 않는다.
2. **검사 목록과 가짜 입력을 만든다.** `tests/suites/M01.txt`에 §5의 정확한 노드를 등록한다. OS 임시 config·DB·가격 저장소만 사용하며 운영 ROOT 접근은 실패다. 종료 전용 검사를 제외할 때 이유를 기록한다.
3. **유지 helper를 먼저 옮긴다.** ADR·분류 보강 및 필요한 함수는 `market/`, `runner.atomic_write` 소비는 기존 `atomic_io.py`로 모은다. import와 합성 동작을 대조한 뒤 종료 폴더 의존을 없앤다. 새 L1 자동선 구현은 M06에 남긴다.
4. **공유 입구와 종료 코드를 함께 정리한다.** 조 1 예외로 MCP 5개·사이클 문맥·화면·라우트·자산·감시·전송 연결을 제거한 뒤 선별·섹터·사이클·옛 위험/아침 CLI와 루트 33개를 제거한다. 사이클 DB는 그대로 둔다. `code_hashes`는 현존 파일만 읽으며 과거 내용은 Git 커밋으로 재현한다.
5. **선별 결과 의존을 끊는다.** `priority-review.json` 대신 `{target_trade_date, completed, failed, status, provenance, sha256}`를 쓰도록 Q09에서 확정한 현재 run 대응만 적용한다. 없는 값은 성공으로 채우지 않는다. 수집·가격 품질·저장을 유지하고, 본격 C9 제공은 M03·성공 판정 정비는 M12에 인계한다.
6. **보관 도구와 합성 검사를 만든다.** 아래 계약으로 계획·ZIP·독립 검증·낱개 제거·중단 재개를 구현한다. 실제 원본을 시험 폴더로 복사하지 않는다. 운영 목록 작성·DB 참조 대조·보관·삭제는 다음 별도 단계로 넘긴다.
7. **격리 검사와 인계를 마친다.** §6 명령의 영수증에서 가드 사건·실행/제외/차단을 확인한다. M02·M03·M05·M06·M07·M09·M10·M12에 변경 경계를, M13에 보관 함수·보호 목록·미처리 항목을 인계한다. 미결에 걸린 검사를 통과로 간주하지 않는다.

보관 도구의 **권장 입력 계약**:

```text
archive_retired(manifest, archive_dir, apply=False)
manifest = {
  module_id: "M01" 또는 "M13",
  source_root: 명시한 자료 root 한 곳,
  entries: [{
    relative_path, classification, producer_evidence, reference_check,
    files: [{relative_path, size, sha256}]
  }]
}
```

구현 검사의 `source_root`는 OS 임시 합성 root만 허용한다. 운영 적용에서는 M01은 `P/runtime`·`WB/runtime`, M13은 여기에 `P/llm`을 더한 범위 중 한 곳을 명시한다(§8.6). `entries.relative_path`는 source_root 기준, `files.relative_path`는 entry 기준이다. `reference_check`에는 확인 범위·시점·미해결 참조를 기록한다. 보호 자료·인증·DB·고정 참조·미확인 항목과 원바이트 없는 재생 recipe는 적용을 거부한다. 반환값은 계획/거부/보관/삭제 결과, ZIP 경로·SHA, 파일별 검증 결과·미처리 이유이며 원문·비밀값은 기록하지 않는다.

기본 `apply=False`는 계획만 반환하며 파일 쓰기·ZIP 생성·삭제가 0이다. 적용은 root 내부 정규 파일만 받고 루트 자체·`..`·링크·정션·중복·대소문자 충돌·원본 아래 보관 위치를 거부한다. ZIP을 닫고 독립적으로 다시 열어 경로·수·크기·파일별 SHA를 대조한 뒤에만 검증된 파일로 게시한다. 삭제 직전 원본과 목록을 다시 대조하고 잠금 등으로 교체를 막는다. 확인할 수 없으면 보존한다. 검증한 낱개 파일만 제거하며 변경·잠금·보관 오류·부분 실패를 성공으로 바꾸지 않는다. 재개는 같은 계획·ZIP 해시와 검증 영수증을 확인해 남은 동일 파일에만 적용한다.

### 7. 브랜치·커밋 방법 (§8.5)

**승인 후 구현 때** WB 브랜치 `module/M01-종료기능`을 M00 병합 결과에서 만든다. 승인 범위만 스테이징해 staged diff를 확인하고 로컬 커밋한다. 공통 `D:/.git`에서는 문서와 루트 `P/scripts` 삭제를 **모듈 브랜치 없이** 별도 커밋하고, 두 저장소 커밋 해시를 이 문서의 구현 기록에 남긴다. 검수 전 병합·push·공개하지 않는다. runtime·DB·인증·보관 ZIP은 코드 커밋에 넣지 않는다.

M12-Q05와 같은 계약 질문이다. C9 제공 M03·소비 M12라는 소유권은 확정이며 없는 값을 임의로 채우지 않는다.

### 9. 운영 적용(Claude, 사용자 승인)

이 단계는 **Codex 구현 범위와 모듈 구현 완료 기준에서 제외**한다(§8.2).

1. Claude가 사용자 승인 뒤 실제 참조 지도·DB 경로·고정 해시를 대조해 정확한 보관 목록과 전후 확인 범위를 정한다. 실행·쓰기 주체가 남으면 보류하며 보호 자료·DB·인증은 기본 보존한다.
2. `recent-screen`(`screening/projection.py:20`), `sector-focus`(`sectors/focus.py:197`), `sector-projection`(`sectors/projection.py:60`) 등은 생산자 근거가 있는 **후보**다. 가격·원문이 섞인 날짜 폴더를 통째 처리하지 않는다.
3. 승인된 목록만 ZIP+파일별 해시로 보관하고 독립 복원 대조 후 동일 낱개 파일만 제거한다. 실제 DB 대조·실제 대시보드 확인이 필요하면 승인 범위에 포함해 전후 해시와 발생한 쓰기를 기록한다. `--offline`을 DB 무변경 보장으로 취급하지 않는다.
4. 보관·삭제·보류 영수증과 전후 파일 수·크기·해시를 남기고 미처리 자료는 M13에 인계한다. 합성 검사 성공과 운영 정리 완료를 별도 보고한다.
