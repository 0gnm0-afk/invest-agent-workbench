# M11 조사 스킬

작성: 2026-11-17 · 상태: **§8 반영 개정안·사용자 승인 전** · 상세 설계 개정 · 판정: 설계 가능 / 설계 검토 가능

입력: [3단계 설계](<../3단계 설계.md>) 전체, **특히 §8을 앞 절과 기존 초안보다 우선**한다. [ver3.1](../투자에이전트ver3.1.md), [기능 목록](<../2단계 기능 목록 초안.md>), [용어집](../용어집.md)을 함께 따른다. 확정은 §8의 결정, 권장은 구현 방법이다. 이번에는 문서만 개정했으며 스킬·코드·운영 자료 변경과 시험 실행은 하지 않았다.

## 설명서

### 1. 하는 일

새 조사 스킬 이름은 **eps-research**다. 저장된 자료와 사용자 생각을 먼저 읽고 필요한 조사를 Claude Code의 deep-research 스킬에 맡긴다.
리포트의 전제 → EPS 증가분 → 검증할 가설 순서로 정리하고, 근거와 남은 질문을 저장한다.

### 2. 입력과 출력

입력은 종목·산업, 리포트, 질문·기간, 기존 가설이다. 출력은 근거가 붙은 설명, 반대 근거·미확인 항목, 저장 ID다. [이익 추정치 상향](../용어집.md)과 실제 분기 실적은 구별하고 자료에 없는 숫자는 채우지 않는다.

### 3. 저장 위치

절차는 프로젝트 `.claude/skills/eps-research/SKILL.md`에 둔다. 조사 결과·원문·발언은 M02를 통해 기존 지식 DB에 저장한다. 보고서·논의·계획은 M05가 맡는다. 새 DB는 만들지 않는다.

### 4. 다른 모듈과의 연결

- **C1(§8.4):** M02의 저장 함수를 사용한다. M11은 DB를 직접 고치지 않는다.
- **C5(§8.1·§8.4):** 조사만으로 감시를 등록하지 않는다. 보유 종목의 가격 위험 자동 감시는 M07의 별도 기능이다.
- **C6:** 도구 이름·인자는 M09가 관리한다.
- **C8(§8.2):** 구현 검사는 임시 합성 자료로만 한다. 실제 조사와 저장은 별도 운영 적용이다.

### 5. 이번 개편에서 바뀌는 것 / 그대로인 것 / 없어지는 것

- **바뀜:** `eps-research`가 deep-research 결과를 대화로 받아 EPS 질문에 맞춰 정리한다. 옛 워크벤치 스킬은 4단계에서 보관한다.
- **그대로:** 출처·날짜·원문 보존, 사용자 생각과 AI 해석 구별, 저장 후 재조회, 사용자의 최종 판단.
- **없어짐:** 조사 절차의 Telegram 강제 검색·36조합 계산. 매매 단위는 세션에서 정하고 계획의 가설 검증일·반증 조건·검증 전 비중을 쓴다.

### 6. 쓰는 법

세션에서 “이 리포트의 전제와 EPS 가설을 정리해줘” 또는 “저장한 가설을 이번 분기 실적으로 다시 봐줘”라고 요청한다. 보고서만 요청하면 그 범위만 다룬다. 계획은 사용자가 이어서 논의할 때 초안으로 넘기며 자동 채택하지 않는다. deep-research를 사용할 수 없으면 조사 미실행으로 알린다.

### 7. 사용자가 직접 확인하는 방법

합성 리포트로 기존 생각을 먼저 읽는지, 전제·EPS 영향·반대 근거를 구별하는지, 저장 ID로 다시 읽을 수 있는지 확인한다. 실제 종목 조사·스킬 호출·운영 DB 저장 확인은 아래 **운영 적용(Claude, 사용자 승인)**에서 별도로 한다.

## 작업 지시서

### 1. 범위와 목표

**확정:** 조 2, 선행 M00·M01. 프로젝트 `eps-research` 스킬을 만들고 Claude Code의 `deep-research` 스킬을 호출해 결과를 대화로 받는다(§8.5). 새 조사 엔진·MCP·수집기·EPS 자동 추정·벡터 DB는 만들지 않는다. 설치·구독 추가나 다른 API로 대체하지 않는다.

프로젝트 규칙의 옛 스킬 안내와 36조합 문구도 M11이 바꾼다. 사용자 확인을 받은 뒤 “매매 단위는 세션에서 정하고 계획 기록의 가설 검증일·반증 조건·검증 전 비중을 쓴다”를 반영한다. 확인 전에는 해당 변경을 적용 완료로 보고하지 않는다. **이 문서 개정은 그 사용자 확인을 대신하지 않는다.**

새 활성 안내는 `eps-research`를 쓰되 과거 분석건·snapshot에 저장된 `qualitative_skill`은 바꾸지 않는다. 서비스 문구는 M05, MCP 설명은 M09, 화면 문구는 M05·M10이 자기 소유 파일에서 연결한다. 사용자 전역의 옛 스킬·Codex 설치본은 수정하지 않는다.

| 단계 | 필수 입력·동작·출력 |
|---|---|
| 맥락 읽기 | 정확한 stock_key/topic으로 `investment_context`; 식별이 모호하면 `knowledge_search`. history/unresolved/next_steps 페이지를 독립적으로 끝까지 읽고 필요한 원문은 `knowledge_note_read`·`knowledge_source`로 확인한다. 분석 키가 있으면 `analysis_collaboration_read`로 채택 버전·미정 질문을 먼저 읽는다. |

| 저장·재조회 | 문서·조사 결과는 `knowledge_ingest`, 해석·가설·질문·다음 행동은 `knowledge_note`로 저장한다. 실제 발언만 author=user, AI 결과는 author=ai다. `knowledge_summary`에는 evidence ID·expected_revision을 쓴다. ID·verified·revision과 재조회 일치를 확인하고 충돌은 재조회한다. 원문 덮어쓰기·맹목 재시도는 금지한다. |
| 논의·계획 인계 | 사용자 논의가 이어질 때 분석건·고정 snapshot·원문 ID를 M05로 넘긴다. 가설 검증일·정성 반증 조건·검증 전 비중은 사용자 값 또는 미정 그대로다. **비중은 분모를 포함한 사용자 원문 문자열이며 숫자로 환산하지 않는다(§8.5).** 보고서 저장·논의·계획 초안·채택·체결은 별개다. |

과거 보고서는 기존 snapshot_id로 읽는다. `analysis_read`가 새 snapshot을 만들 수 있으므로 새 입력이 필요할 때만 생성한다. 원문 전체 내보내기는 별도 명시 요청 때만 한다. Telegram 뉴스 원문 저장·보류된 뉴스 경로의 우회는 넣지 않는다.

### 3. 건드리면 안 되는 것

- M02 저장 구현·DB schema, M05 분석·계획, M06 작도, M07 감시, M08 계좌, M09 도구 인자, M10 HTTP/shell은 직접 수정하지 않는다.
- `.mcp.json`, 사용자 Codex 설정·설치 스킬, `.venv`, 인증·DPAPI·키·토큰·계좌번호는 읽거나 바꾸지 않는다.
- 원문·DB·개인 입력·방법론·확정 계획·과거 snapshot·보호 원자료 8,851파일을 보존한다. 발언·합의·체결을 만들지 않는다.
- 뉴스·계좌 조회·시장 수집·Telegram·주문·환전·예약을 구현 검사에 쓰지 않는다. 조회 전용 설정과 중지 예약을 유지한다.
- 이번 개정에서는 위 스킬·규칙·코드·검사·보관 파일을 만들지 않는다. STATUS·DECISIONS·3단계 설계·용어집 수정, 시험 실행, 커밋도 하지 않는다.

### 4. 단계별 구현 순서

1. M00의 §8.2 실행기와 M02 저장 fixture를 받는다. `tests/suites/M11.txt`에 노드를 등록하고 프로젝트 스킬·규칙 소스만 읽는 임시 입력을 준비한다.
2. `eps-research`를 작성한다. 산업·종목 조사·가설 후속 검토에만 적용하고 단순 계산·작도·코드 작업에는 적용하지 않는다. `deep-research` 호출과 대화 반환을 명시한다. 실제 호출 검수는 운영 적용으로 분리한다.
3. 맥락 → 전제 → EPS 증분 → 가설·반대 근거 → 저장·재조회를 반영한다. 사용자 확인 후 프로젝트 규칙의 옛 안내·36조합 문구를 고친다. 확인이 없으면 이 변경을 남은 항목으로 보고한다.
4. 옛 워크벤치 스킬 전체의 보관본·파일별 해시를 대조한 뒤 활성 위치에서 아카이브로 전환한다. 과거 기록의 식별자·전역 설치본은 유지한다. M05·M09·M10에 새 이름·문맥 복사 안내와 소유 파일을 인계한다.
5. M05의 가설 세 칸과 비중 원문 규약에 인계 예시를 맞춘다. 후속 모듈 서비스·schema는 미리 수정하지 않는다.
6. 합성 리포트·가설·반환 예시로 §5를 검사한다. 실제 조사·운영 DB 확인은 구현 통과와 별도로 남긴다.

### 6. 검사 명령

§8.2의 확정 계약이다. 향후 M00 구현·설명서 승인 뒤 **WB에서** 실행하며 이번 개정에서는 실행하지 않는다.

```powershell
.\.venv\Scripts\python.exe -B tests/run_isolated.py --module M11
```

선택 목록은 `tests/suites/M11.txt`이며 M11이 소유한다. 개별 재검사는 같은 실행기의 `--node 노드ID`를 쓴다. 위 노드와 필요한 M02 합성 저장 검사만 등록한다. 기존 `unittest discover`·옛 실행기·전체 subprocess 시험은 직접 실행하지 않는다.

C8은 외부 DNS/connect·운영 runtime/DB·인증 파일·Windows 사용자 환경변수 접근을 금지한다. OS 임시 합성 파일·DB, 127.0.0.1·socketpair, 같은 가드를 상속한 임시 fixture 자식은 허용하되 M11은 필요한 합성 저장만 쓴다. 영수증 JSON은 OS 임시 폴더에 둔다. 실제 deep-research·브라우저·운영 지식 DB는 호출하지 않는다.

### 7. 브랜치·커밋 방법

**향후 구현:** WB 검사·suite와 옛 워크벤치 스킬 제거는 `module/M11-research-skill`에서 다룬다. 프로젝트 `.claude/skills/eps-research/`, `.claude/rules/investment-session.md`, 보관본·모듈 문서는 공통 `D:/.git`에서 **모듈 브랜치 없이** 경로별 diff를 검토해 커밋한다(§8.5). 각 저장소 커밋 해시를 이 문서에 남긴다. 다른 작업·운영 자료·자격·임시 결과는 포함하지 않는다.

**현재 개정:** 이 문서만 수정한다. 브랜치 생성·stage·커밋·STATUS·DECISIONS 갱신은 하지 않는다.
