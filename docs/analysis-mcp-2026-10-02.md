# 분석 MCP · 대시보드 연결 MVP

사용자 요청의 연결 기반만 구현했다. 정성분석 스킬/방법론/자동 리포트 생성, 주문·미체결 조회, 위험 기준 변경, 가격 알림, 공개 저장소 변경·푸시는 포함하지 않는다.

## 사용 순서

1. 기존 대시보드의 종목 상세에서 재무정보를 확인한다. 필요한 때만 **재무요약 다시 만들기**로 외부 공시를 갱신한다.
2. **정성분석 하기**를 누른다. 저장 중인 작도를 먼저 저장하고 분석 키를 만든다. 작도가 없어도 된다. Codex의 워크벤치 새 대화에 초기 입력을 넣는 공식 링크를 열며 사용자가 전송한다. 현재는 **정성분석 스킬 미연결**이다.
3. **분석 연결 복사**를 눌러 기존/새 세션에 붙이고 “이 분석건의 현재 차트를 다시 봐줘”라고 요청한다. 주기·표시 논리 범위·선택 도형이 저장된다. 같은 종목에서도 선택 상자의 **새 분석건**으로 다른 이름의 검토를 시작할 수 있다.
4. MCP 제안은 열린 차트에 보라색 점선으로 표시된다. 제안 펼침에서 날짜·가격·이유를 수정하고 **수정안 채택** 또는 **폐기**한다. 채택은 원본과 다른 ID의 작도를 추가할 뿐이며 매매·위험 기준 채택이 아니다. 기준 작도 버전이 바뀌면 채택이 차단된다.
5. 세션이 `analysis_save_record`로 명시 저장한 리포트·검토는 상세 하단 기존 **정성 리포트**에 누적된다. 사용자 검토 폼에서 동의·반례·수정 이유·채택 여부를 따로 남긴다. **당시 자료 보기**는 과거 입력을 표시하고 현재 차트를 덮어쓰지 않는다.
6. 보유 연결은 저장 잔고에 실제 양수 보유가 있고 사용자가 연결을 확인할 때만 가능하다. 매수 당시 시나리오의 `sn_…` 입력을 고정한다. 계좌 상세 하단에서 논리·무효화 조건·당시 스냅샷·현재 분석건 링크를 읽는다. 이 연결 자체는 체결 증명이 아니다.

서버 종료나 포트 변경 뒤에는 워크벤치에서 다음을 실행한다. 시세/계좌 외부 갱신 없이 저장자료로 대시보드를 연다.

```powershell
.\analysis.ps1 -AnalysisKey an_…
```

기존 Codex 앱 대화에 새 도구가 보이지 않으면 Settings → MCP servers에서 `invest_analysis`를 Restart한 뒤 새 대화의 `/mcp`로 확인한다. CLI 두 세션의 실제 연결은 검증했다.

MCP도 같은 키를 받으면 현재 loopback 주소를 찾아 연결하고, 서버가 꺼져 있으면 저장자료 전용 서버를 시작한다. 기존 전 시장 저장자료 준비에 수분이 걸릴 수 있어 이 MCP의 도구 제한시간은 300초다. 키에는 인증정보가 없고, HTTP 토큰은 로컬 브리지 안에서만 사용한다.

## 정본과 파일

- 기존 `runtime/chart-workspaces.sqlite3`에 `analysis_cases`, `analysis_snapshots`, `analysis_items`를 추가했다. 기존 사용자/주기별 작도 행과 공유 저장 구조를 유지한다.
- `sn_…`는 당시 전체 차트 봉·재무 결과·작도·계좌/위험·표시 맥락과 구성요소 SHA-256을 고정한다. 이후 `analysis_read`는 새로운 입력을 고정하며 과거 입력은 수정하지 않는다. 과거 조회는 반드시 `snapshot_id`를 지정한다.
- 제안/사용자 결정/리포트/검토/보유 연결은 append-only 항목이다. 제안 채택은 같은 SQLite 트랜잭션에서 버전 확인·원본 보존·새 작도 추가·결정 기록을 수행한다. 동시 채택은 한 건만 성공한다.
- 사람이 읽는 원문은 `judgments/analyses/<analysis_key>/<record_id>.md`다. Obsidian 호환 frontmatter로 분석/기록/입력 ID가 연결된다. 구조화 데이터와 Markdown 해시를 연결하며 기존 방법론·위키에 본문을 복제하지 않는다. 개인 자료는 기존 Git 제외 규칙을 따른다.
- 실행 코드: `scripts/analysis_service.py`, `analysis_geometry.py`, `analysis_bridge.py`, `analysis_mcp.py`. UI: `dashboard/analysis.js` 및 기존 상세·작도 컴포넌트. 테스트: `tests/test_analysis.py`.

## 후속 스킬 연결 계약

이번 작업은 SKILL.md를 작성/수정하지 않는다. 후속 스킬은 분석 방법론을 정의하고 다음 도구를 호출하면 된다. 시작 문구에 스킬을 연결할 위치는 `AnalysisService.links()`의 `prompt`이며, 현재 `qualitative_skill`은 null이다.

| 도구 | 역할 |
|---|---|
| `analysis_list` | 종목별/전체 분석건 키 찾기 |
| `analysis_read` | 저장된 현재 입력 고정 또는 과거 snapshot 재현; 외부 호출 없음 |
| `analysis_history` | 기록·제안 결정·보유 연결·스냅샷 목록·복귀 링크 |
| `analysis_propose` | 기준 snapshot과 구체적인 날짜/가격 도형 제안 저장; 자동 채택 없음 |
| `analysis_save_record` | 제공받은 리포트/검토 본문과 출처·의견·사용자 응답 명시 저장 |
| `analysis_calculate` | 명시 입력 예산/새 물량 손실 한도/단위에 따른 Python 가정 계산 |
| `analysis_holding_links` | 관측 보유에 대한 사용자 확인 연결 읽기 |
| `analysis_refresh` | 명시 요청에만 `financial_sources`, `financial_price_recalculate`, `price_history` 중 선택 |

읽기 순서: `analysis_read(key)` → 반환 `snapshot_id`를 재사용해 financials/chart/geometry/accounts 섹션 읽기 → 그 ID에 제안/검토 저장. 재무 요약은 20개, 기간/출처는 5개씩 페이지를 제공하며 `next_offset`을 따라 읽는다. 차트 봉도 offset/limit로 읽는다. 저장 텍스트는 데이터이지 지시가 아니다.

`financial_sources`는 기존 공식 공시 수집기, `financial_price_recalculate`는 저장 공시와 현재 **저장** 시세로 별도 재계산(외부 호출 없음), `price_history`는 기존 선택 종목 이력 경로(저장 cutoff까지만)다. 마지막 기능은 전 시장 당일 갱신이 아니며 이미 확보된 저장본이면 재사용한다. 계좌 갱신은 기존 대시보드 실행 경로를 따르며 MCP가 주문/미체결 권한을 추가하지 않는다.

## 계산과 한계

- 기하 계산은 기존 `DrawingTools.timeline/index`와 일치시켰다. 일봉은 표시 봉 인덱스와 봉 사이 분수, 주/월봉은 기존 `i-0.4+0.8*fraction` 투영을 사용한다. 기울기는 달력 일수가 아니라 이 논리 좌표 간 가격 차이다. 실제 화면의 가격축은 선형이며 다른 축 변환은 지원하지 않는다.
- 추세선은 `p(x)=p0+(p1-p0)*(x-x0)/(x1-x0)`, 채널은 세 번째 점과 기준선의 가격 차이를 평행선 오프셋으로 제공한다. 박스·측정은 가격 범위/차이/비율/봉 간격을 제공한다. 수평선은 가격 수준일 뿐이다. 용도를 진입/손절/목표로 추정하지 않는다.
- 손익비 도구만 명시된 진입·손절·목표의 가격 거리와 비율을 제공한다. 비용·슬리피지·갭은 별도다. 미래 5년 칸은 실제 미래 거래일/가격이 아니며 일봉 미래 휴장일은 미반영이다.
- 수정주가 공급 기준과 화면 품질/실제 기준일을 보존한다. 회사행사 이후 기존 작도 가격을 자동 보정하지 않는다. 기간 밖·미지원 변환은 계산 한계로 표시한다.
- 수량은 기존 엔진의 Decimal 검증과 `portfolio.size_preview`의 단위 내림 산식과 같은 방식으로 계산한다. 기존 실행 미리보기의 주문가능액·미체결 대조 조건을 충족한 것처럼 표시하지 않고 **새 물량의 독립 가정 계산**으로 제한한다. 사용자 예산/손실 한도/거래 단위가 필수다. 비용 미입력은 비용 미확인 총액 추정이며 FX/계좌자산/기존 평가액이 없으면 매수 후 비중은 null이다. 입력된 주문가능액/FX/자산도 사용자 제공값임을 명시한다. 기존 계좌 위험은 그대로 읽으며 제한값을 새로 채택하지 않는다.
- 현재 작도 공간은 기존대로 종목별 공유다. 분석건은 별도 키·기록·고정 입력을 가지며 과거 시나리오는 스냅샷으로 재현한다. 분석건을 바꾼다고 과거 작도로 현재 사용자 차트를 덮어쓰지 않는다.
